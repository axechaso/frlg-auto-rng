# 火红/叶绿全自动乱数工具

这是一个面向 Nintendo Switch 火红/叶绿（Gen 3）的自动乱数初步实现。当前主流程使用 Ten Lines 源码搜索目标，由 Python 自动选择方案并填写 2.0 ECS 参数，再交给固定版本的 EasyCon 1.6.4a 控制单片机、采集卡和本地 OCR。

新流程不需要部署 Qwen、vLLM、Ollama 或其他 AI 服务。仓库中原有的 PyEasyCon/VLM 执行链仍然保留，但与本流程相互独立。

详细开发交接请先阅读 [新设备与新对话交接文档](docs/HANDOFF.md)，功能边界和验收状态见 [自动乱数首版说明](docs/INITIAL_AUTO_RNG.md)。

当前绿色版发布为 `0.2.2`。该版本包含完整整包更新器，并修复 0.2.1 发布包中文扩展标签文件名在部分 Windows 环境下乱码、导致 ECS 生成失败的问题；旧版可直接通过更新器升级。源码模式不执行程序自更新。更新只替换程序目录，不会覆盖 `%LOCALAPPDATA%\FRLG-Auto-RNG` 中的配置、日志、进度、Seed 表或设备标签覆盖。

开发约定：每完成一轮较大的功能改动并通过本地验证，就提交并推送到私有 `origin`，让 GitHub Actions 自动复核；零散小修改可以合并到下一轮大改一起推送。

## 当前完成情况

- GUI 提供“SID 查找”“TID 乱数”“野生 / 静态”“孵蛋（测试）”四个输入选项卡；“TID 实测表”位于第三页，“运行日志”常驻末尾。EasyCon 设置、运行按钮和结果区共用；非必要说明收进带标题的悬浮帮助，状态、错误、安全确认和危险警告保持常驻。勾选“高级模式”后才额外显示“脚本测试（高级）”页，同时把已登记脚本、标签、EasyCon、OCR 和兼容运行器的指纹不一致降级为明确警告；Seed 方案旁的正式版/时间轴版选择会实际用于普通、孵蛋及御三家生成，自选 ECS 仍只用于直接测试。
- 共通设置可选择“命中后更新预校准”，默认关闭。开启后只在完整命中时保存 Seed 与当前流程允许的帧修正，记录按游戏、机型、Seed 模式、Seed 启动方案、脚本入口和流程类型隔离；御三家使用独立上下文，TID/SID 不参与。正式版普通定点只复用 Seed，其他受支持流程和时间轴版可复用帧修正。
- 顶部“存档信息”按 PokeFinder 的 Profile 思路保存名称、游戏版本、TID、SID，并额外保存本工具需要的 Switch 机型。可新建、编辑、复制、删除或设为当前；选择后自动同步四页相关字段，“未选择（手动输入）”不会覆盖现有输入。
- 整个页面可以纵向滚动；结果框拥有独立滚动条，较小屏幕也能看到底部。
- 野生/静态页提供六项 IV 的独立最低/最高输入框，以及不限、6V、0A、0S、0A0S 预设。
- 支持闪光、性格、性别、特性、觉醒力量、Seed 模式和最大 Advance 筛选。
- Seed模式3为 `stereo_h_start`（立体声 / HELP / 封面Start，手柄X），正式版、TV时间轴版与孵蛋使用同一映射，不再误用LR/A或单独禁用火红模式3。当前官方NX表的该列仍为空；模式支持与数据可用性分开，缺表时沿用“找不到目标Seed”提示，绝不挪用LR/A数据。旧模板及旧更新缓存会在生成时转换；已有运行工程和旧打包版需重新生成/打包才生效。
- 日版御三家临时分支使用 Seed 模式10（`mono_h_a` / HELP / 封面A），仅支持图鉴1/4/7。选择 TID/SID 页的日文连续御三家流程时，工具自动切换 `fr_jpn_nx`/`lg_jpn_nx` Seed 表，并注入日版性格、等级和能力值识图；性格标签识别失败会停止反查，不会默认判为天真。该分支保留1.1.8的自动反查、Seed校准和帧校准，尚未完成Switch实机验收。
- Ten Lines 搜索结果先按六项 IV 总和从高到低选择；同一总和下选择 Advance 最小的可行初始 Seed。
- 自动生成经过参数替换的 2.0 ECS 工程，并检查脚本、1150 个标签、OCR 模型、EasyCon 版本及 ECS 语法。
- SID 采集由用户填写每只宝可梦的初始等级和六项努力值；Python 注入完整第三世代种族值/性别数据，ECS 据此计算合法能力范围，闪光雄性摘要页使用独立的 `闪公图标` 标签。
- 孵蛋页可以把 Ten Lines Egg 页得到的同 Seed、Held/生成帧、Pickup/领取帧和双亲资料写入正式入口的实验性孵蛋 ECS；该运行副本使用正式版普通 `WAIT`，不再默认复制 TV 时间轴入口。
- TID/SID 页接入英文/日文 1.3.7 脚本，支持乱数与穷举、固定延迟自动回填、取名、特殊号码和本地标签识别；目标 SID 的 TID 生成链搜索窗口为前 1,000,000 ADV。英文穷举可把实际 TID/SID ADV 动态衔接到 1.1.8 御三家流程。
- TID 优先接入用户确认的 `NS火叶TID-SID到御三家球前存档-测试.ecs`，同步英日文按键与帧换算修正。工具仍分“TID → 球前存档 → 1.1.8 御三家”三阶段，球前路线原样复用且只走一次；HOME_BUFFER 自适应默认关闭。更新后须重启并重新生成，首次使用新版建议先做固定延迟检查（完成后自动回填）。
- 当前TID版本为 `2026-08-28-r3`：菜单保留查看训练家卡片后的光标，球前存档在 X 后等1000ms，只按一次 `DOWN / WAIT 500` 到SAVE，再按六次 `A`（各1500ms），最后 `UP / WAIT 500 / A / WAIT 2500`。二楼/一楼/镇上路线、OP检测、NS2补偿和第三阶段不变；保存结果仍需实机确认。
- TID 穷举 OP/F1/F2 起点默认全为0（由脚本自动使用可执行最小值）。TID页参数自动保存；穷举逐轮记录检查点，下次重新生成并开始时默认续跑同参数任务，当前未完成点重新观察，不跳过结果。
- “停止EasyCon”通过每次运行独立的停止文件通知后台，不再依赖跨命令窗口的CTRL_BREAK；超时5秒后清理本次运行器及其EasyCon进程树，不按程序名结束其他任务。
- TID 运行时自动积累实测表，按火红/叶绿、Switch 1/2 及完整参数分别统计，可查询号码、查看设置、导出 CSV；只记录 TID，不记录 SID、SID ADV 或 F3。
- TID 可选择“先检测固定延迟，完成后自动运行计划”：四项测量值与实际OP修正自动回填，后台重新生成并预检后继续，无需再次点击开始。穷举御三家另有“取得任意TID后继续”选项，去噪可独立开关（默认保留）。
- SID 查找页逐只采集队伍闪光宝可梦，由 Python 恢复 Method 1/2/4 PID、求 PSV 交集并给出 SID 候选与最早建档 ADV。
- 野生/静态页可在开启“SID遍历模式”后按对应奇偶 ADV 逐个尝试低帧闪光目标，并持久化断点；每个 SID 的目标搜索下限继承页面“最小 Advance”，上限为 3000。未取名从奇数 ADV 1901 开始，取名从偶数 ADV 1900 开始，每次推进 2 ADV。高级模式可填写同奇偶的自定义起点，使用独立进度，不影响 TID 乱数或 TID→御三家流程。
- GUI 启动后会静默执行一次端口/采集卡检测；串口与采集卡均为下拉框，采集卡显示 EasyCon 序号和设备名。重检时保留仍在线的当前选择，否则选择数字最小的可用项；启动检测失败只写入结果区，不弹窗打断填写。
- “高级模式”旁提供“HOME_BUFFER 稳定低分自适应”开关，作用于 1.1.8 普通/孵蛋、TID 1.3.7 和 SID 查找的生成副本且默认关闭。开启后，95 分以下的状态必须连续 3 次得到完全相同的唯一最高分，且不低于 90，才会把本次运行的有效阈值降到该分数；其他识图阶段不受影响。
- 公共工具区可直接“检查/更新 Seed 表”。它从 Ten Lines 官方生成站点下载火红/叶绿 NX 二进制表，由同一份数据生成 EasyCon 两份 ECS 表；四个文件全部校验且正式版/孵蛋版均通过真实 1.6.4-a `format` 后才同时切换。绿色打包版内置此功能，不要求用户另装 Python 或调用外部更新脚本。
- 点击“开始运行”并成功启动进程后，界面自动切换到“运行日志”页；普通、孵蛋、TID、SID、连续御三家和高级脚本测试都会实时读取各自日志文件，方案与预检结果仍保留在下方独立区域。
- “运行日志”页会从已输出的匹配分数中定位反复低于门槛的疑似标签，并支持为当前采集设备多选、选择文件夹或批量拖入重做后的同名 `.IL`。设备标签保存在独立覆盖层，先验证原始语料再应用到生成工程；合法覆盖不需要高级模式，也不会关闭原包指纹检查。详见 [设备标签诊断与覆盖](docs/DEVICE_LABEL_OVERRIDES.md)。
- 当前自动执行后端严格锁定 EasyCon 1.6.4a；不接受 1.7.0。
- 高级脚本测试页可在当前 1.1.8 包的正式版、时间轴版和自选 `.ecs` 之间切换；前两项自动解析标准入口，自选项保留任意工程测试。运行后端可在“正式工具兼容运行器”和“原始 1.6.4-a CLI”之间做 A/B；两种方式都保存独立日志，不经过参数生成器。悬浮提示不使用鼠标移动高频回调；监视预览的处理和显示上限约为 30 FPS，拖动主窗口或监视窗口时会暂缓图像转换，静止后自动恢复。

以下功能仍不能视为完成实机验收：狩猎区、普通碎岩、漫游三圣兽、孵蛋长跑，以及所有路线的长期稳定性。受限路线只生成搜索计划，不开放“开始运行”。

## TID 参数与穷举续跑

TID 页第7区提供“开始时继续同参数的上次穷举进度”（默认开启）和进度查看。参数在修改后自动保存，关闭时再保存一次；重新打开后直接恢复，不必重新填写。起点默认0不代表实际从游戏第0帧操作，而是使用原脚本的最小可执行起点。已经手填并保存的非零值会保留。

穷举保存 OP/F1/F2 搜索偏移、当前层级、轮数、实际OP恢复修正和HOME_BUFFER/关闭等待。停止时正在做的那个点，下次重新进行去噪观察；已经命中的TID阶段不续跑。取消续跑勾选会从填写的起点重新开始。游戏、机型、语言、参数、连续流程选项或脚本版本不同不会共用进度。当前仅支持新版球前存档TID模板的穷举阶段，不恢复御三家领取中途的游戏状态，也不自动迁移更新前未记录的进度。

运行中关闭窗口可选“停止并保存后关闭”或“保留后台继续”；后者仍持续记进度，重新打开后须先停止旧运行器再开始，同一任务/端口不会重复运行。打开窗口本身不会操作游戏。固定延迟检测在后台完成时，测量结果也可在下次打开工具时自动回填，前提是用户未修改相应参数。

资料位于 `%LOCALAPPDATA%\FRLG-Auto-RNG\tid_settings.json` 和同目录 `tid_progress\`。换设备如需迁移，应停止运行器后复制这两项以及所需模板。源码版与新版绿色打包版共用该位置；绿色版已包含TID r3、参数记忆、穷举续跑和停止进程修复，无需安装Python。旧打包目录不会自动更新，需解压并运行新包；旧运行工程仍需重新生成。

## 存档信息

窗口顶部的“当前存档”是工具参数档案，不会读取、写入或删除模拟器/游戏中的实际存档。点击“管理存档”可新建、编辑、复制和删除档案，也可在管理器内设为当前。选中后会同步：

- SID 查找页：游戏、主机、当前 TID；SID 本身仍由该页反查；
- TID 乱数页：游戏、主机、目标 TID、目标 SID；
- 野生/静态页：游戏、主机、TID、SID；
- 孵蛋页：与野生/静态页共用的游戏和主机。

档案保存在 `%LOCALAPPDATA%\FRLG-Auto-RNG\save_profiles.json`，因此源码版与新版绿色版共用同一份资料。火红/叶绿没有实时时钟电池状态，所以没有照搬 PokeFinder 其他第三世代游戏使用的枯电池字段；Switch 机型是本项目为 NX Seed 表增加的字段。

## 新设备安装

### 1. 复制完整工作区

当前源码通过私有 GitHub 仓库 `origin` 保存。换设备时克隆私有仓库，并检出包含最新功能的已推送分支或合并后的 `main`。不要只复制 `runtime/`；它是生成目录，不是源码。

### 2. 放置外部运行包

安装脚本默认使用以下位置：

```text
%USERPROFILE%\Downloads\NS火叶全自动一键乱数1.1.8\
%USERPROFILE%\Downloads\伊机控-EasyCon-v1.6.4alpha测试版-260518\publish\ezcon.exe
%USERPROFILE%\Downloads\自定义TID SID 御三家乱数多功能包1.3\
```

1.1.8 目录必须包含：

```text
NS火叶全自动一键乱数2.0.ecs
NS火叶全自动一键乱数2.0-时间轴.ecs
NS火叶SID反查-采集测试.ecs
lib\
ImgLabel\
Tessdata\frlg_battle.traineddata
Tessdata\FRLG_EN_ALL.traineddata
```

EasyCon 原始 1.6.4a 压缩包不包含这两份火叶 OCR 模型。安装器会从 1.1.8 的 `Tessdata` 复制到 EasyCon 的 `publish\Tessdata` 并校验 SHA-256。

### 3. 安装并启动

在项目根目录依次双击：

```text
安装-自动乱数首版.bat
启动-自动乱数首版.bat
```

安装器会创建 `.venv`、安装 `requirements-auto.txt`、导入并校验 1.1.8 与 TID/SID 1.3.7 快照，以及准备 EasyCon 1.6.4a OCR 环境。GUI 启动失败时查看：

```text
runtime\launcher.log
```

## 使用流程

### 野生 / 静态

1. 连接单片机和视频源。
2. 选择游戏、主机、野生/静态类型、遭遇地点和目标宝可梦，并填写 TID/SID。
3. 设置六项 IV 范围、最大 Advance、闪光、性格、性别、特性和觉醒力量等条件。
4. 点击“搜索并生成方案”。
5. 检查结果、路线支持状态和 EasyCon 预检。
6. 只有路线允许启动且预检通过后，“开始运行”按钮才会启用。

野生目标可在“出闪后处理”一行开启“道具乱数模式”，并填写队伍空位数 1–5；脚本会按空位数收集携带道具命中。静态目标不支持该模式，关闭时会使用普通目标流程。

### 更新 Seed 表

在“EasyCon 共通设置与工具”中点击“检查/更新 Seed 表”。工具会联网检查 Ten Lines 官方 `fr_eng_nx.bin` 与 `lg_eng_nx.bin`，同时生成 1.1.8 使用的火红/叶绿 ECS 表，并用当前锁定的 EasyCon 1.6.4-a 分别编译正式入口和孵蛋时间轴入口。任何下载、内容指纹或 `format` 检查失败都会保留旧表；成功后当前方案会失效，需要重新搜索/生成。生效文件保存在 `%LOCALAPPDATA%\FRLG-Auto-RNG\seed_tables\current`，上一版保留在相邻的 `previous` 目录。

界面中的“特性：不限”会转换成 Ten Lines 的 `Any`，不会作为名为“不限”的特性参与搜索。

预设与 Ten Lines 一致：

| 预设 | 精确含义，顺序为 HP/攻击/防御/特攻/特防/速度 |
|---|---|
| 不限 | 六项均为 0–31 |
| 6V | 31/31/31/31/31/31 |
| 0A | 31/0/31/31/31/31 |
| 0S | 31/31/31/31/31/0 |
| 0A0S | 31/0/31/31/31/0 |

### 孵蛋（测试）

1. 先在 Ten Lines Egg 页搜索，并记录目标 Seed、Held/生成帧、Pickup/领取帧和游戏设置。
2. 打开 GUI 的“孵蛋（测试）”选项卡。
3. 选择游戏、主机、与 Ten Lines 完全一致的 Seed 模式、蛋种和启动准备模式。蛋种可从下拉框选择，也可直接输入中文名、英文名或全国图鉴编号，输入名称时会自动补全。
4. 填写 Held、Pickup、双亲相性、双亲性别和六项 IV。
5. 勾选实验功能确认后生成脚本。

孵蛋页提供两组 JSON 配置按钮。“保存/载入亲本配置”只处理蛋种、相性、双亲性别和六项 IV，切换 Seed 目标时可以直接复用；“保存/载入全部配置”还处理游戏、主机、Seed 模式、目标 Seed、Held、Pickup、启动准备和 HOME_BUFFER 稳定低分自适应。旧版“孵蛋配置.json”可继续由“载入亲本配置”读取，旧文件没有记录的双亲性别按 A 雌、B 雄补全。实验功能确认不会保存，载入全部配置后仍需当次手动勾选。

Python 当前不重复执行蛋目标搜索；它只接收 Ten Lines Egg 页已经选好的结果。孵蛋 ECS 已通过代码与 EasyCon 1.6.4a 语法检查，但尚未完成本机实机验收。

更新后的正式模板包含 `$孵蛋Held无蛋...` 区间表字段。若生成器提示模板缺少这些字段，说明工具的 `local_assets/easycon118` 仍是旧缓存；重新运行安装/导入步骤刷新缓存，不要手动删除生成器的字段校验。

2026-08-26 的孵蛋更新会在 Pickup 尚未稳定时继续累计“目标 Seed 命中但无蛋”的 Held 区间证据。证据连续确认后只应用临时 Held 跳区，不提前改写正式 Held 累计修正；连续无蛋超过处理上限则明确停止，避免流程在同一无蛋区间无限重试。

孵蛋生成器会固定关闭互斥的“道具乱数模式”，不继承时间轴模板上一次手工测试遗留的开关值；否则入口的运行参数检查会在实际操作前直接拒绝孵蛋。

“启动准备”默认选择完整准备，自动重启、走到 254 步、检查游戏设置并建立基础存档。若已经拥有由该流程建立的 254 步基础档，可选择“从已完成254步准备开始”；脚本会跳过一次性走位、设置检查和存档，随后仍会关闭游戏并完整执行 HOME_BUFFER、Seed 预校准、生成/领取、孵化和个体反查。

孵蛋运行进入 Options 后，会分别识别文字速度、战斗动画、声音和按键模式；每项最多重试 3 次，并在终端输出各候选标签分数，避免页面刚切换时的一次低分直接终止。GUI 会同时把完整输出保存到 `runtime/easycon118/egg-日期_时间.log`，结束后在结果区显示日志尾部。

孵蛋流程支持从游戏内画面启动。关游戏步骤按 1.1.8 原版的 X/A 顺序执行，但会先判断“正确退出/错误退出”，再判断是否需要按 HOME；一次关闭流程最多主动按一次 HOME，避免到达主页后又切回游戏。按 HOME 后一定重新截图，不会继续使用游戏内画面的旧分数，也不会为此降低 95 阈值。

1.1.8 正式版与孵蛋运行副本保留 `HOME_BUFFER` 的 1200 ms 初值和默认 95 阈值。首次命中后锁定本次延迟；未知画面最多原地采样 8 次，间隔 200 ms，仍未知则保持锁定值，不当作“过短”。如果本轮成功画面直到恢复阶段才到达，只要尚未发出恢复按键或确认关闭，就直接接住成功、锁定实际试过的延迟，并输出 `HOME_BUFFER_LATE_SUCCESS`；不会将其关闭再试。开始前的旧游戏画面不适用此规则。只有连续 3 次明确识别普通退出才解除锁定，未知结果会打断这一计数。未锁定时连续 3 次未知可按 50 ms 向上试探，明确普通退出则按 50 ms 向下试探；不再把未知结果写成二分边界，也不再因 1200/1250 的中点不满足最小步长而直接退出。最多 20 轮恢复/试探后仍未确认才停止。

每次试探前先通过 HOME_BUFFER 专用恢复函数确认启动原点：先处理关闭中、休眠菜单和正在游玩状态；主页 Online 图标命中后，还要连续 3 次确认两种正在游玩标签均已消失。90–94 只作为歧义保护，不放宽成功阈值；同一次未完成恢复最多主动按一次 HOME，避免在主页和游戏之间反复切换。未确认原点时不执行启动 A。正式版与时间轴版共用恢复和步长决策，通用关闭游戏、Seed 与奇偶修正不变。若换设备后正确标签长期稳定在 90–94，仍可显式开启公共稳定低分自适应；默认关闭时严格要求 95。

池塘 Seed 预校准和领取后复核曾出现同一 254 步基础档有时成功、有时没有进入战斗。实机观察确认其中一种竞态是冲浪转场吞掉 `X`：随后原本用于选择队伍菜单的 `DOWN` 落到地图上，让人物向下移动一格。运行副本把冲浪确认的第三次 `A` 前等待从 800 ms 延长到 2000 ms；第三次 `A` 后不再依赖固定 5 秒窗口，而是最多约 50 秒等待仓库扩展标签 `冲浪 > 95`。该标签表示冲浪操作已经结束，只有命中后才按一次 `X`，再按原版的 500 ms 菜单展开等待继续；未命中时禁止按 `X` 并安全重启。`火红BAG` 是御三家流程标签，不参与这里的判断。使用甜甜香气后还会在名称 OCR 前最多 4 次只等待重采样 `野生出现/抓捕就绪`，不会把地图或菜单文字当作宝可梦名称。

孵蛋总控把返回值 `2` 解释为“本轮已重启，继续下一轮”，把 `0` 解释为“不可恢复，停止整个流程”。原 1.1.8 时间轴脚本有几条瞬时失败分支虽然已经调用重启，却错误返回 `0`，所以会出现“游戏已经重启，脚本随后仍打印失败并结束”。当前导入的时间轴模板和生成副本都把生成/领取/Seed 复核抓捕动作失败、领取后野生 Seed 反查失败和孵化动作失败改为返回 `2`。首次“不领蛋、只抓野生”的 Seed 预校准一旦完成，领取后未命中目标 Seed 会先校正等待并保持 `$孵蛋流程Seed已预校准 = 1`；领取后野生反查本身失败也保持该状态，下一轮直接重新生成、领取和反查，不再重复整段首次预校准。蛋反查已经确定同一套个体但 Held/Pickup 仍有误差时也保留自动重启校准；无候选、候选仍对应不同个体、超过吃糖上限或数据无效等终止结果则直接停止并保留当前游戏画面，不再先重启游戏。HOME_BUFFER 无可用窗口和时间轴计算无效同样停止，避免无意义死循环。

孵蛋日志包装器以“孵蛋流程测试完成/失败”为正式终止标记。用户取消、运行器异常退出或其他没有到达这两个标记的情况会写入 `[EASYCON_DIAGNOSTIC]` 并返回非零状态，GUI 会明确显示“被取消或异常提前退出”，不再把运行器最后一行“脚本运行完成”误当成 ECS 正常完成。

孵蛋 Seed 预校准不再按本轮 Seed 表差直接改写等待时间。运行副本复用正式版的 Seed 锁定控制器：大偏差先限幅靠近，可信的相邻 Seed 逐索引修正，方向反转后在两个相邻表项之间切换到固定毫秒半步。精确命中后保留 10 次可信反查观察窗；每次可信反查都会推进窗口，但只有 `±1` 结果投方向票，满窗至少取得 3 个方向样本且不平票才修正，避免偶发大波动让保持期无限延长或直接带偏。日志会输出本次/累计索引、查表累计毫秒、固定半步、观察次数、方向票和下轮等待；这只更新 Seed 轴，不改 Held/Pickup 帧轴。

新版时间轴入口为 Held 和 Pickup 各加入固定 `230` 帧预校准，请求公式为“目标帧 - 230 + 动态修正”；例如目标 `1115/3405` 的首轮请求是 `885/3175`。Held 只扫描目标 `±100`，Pickup 保留 `±2000` 宽窗。固定预校准不会被反查改写，后续偏差只写入动态修正；若同一套完整 IV 对应多个候选，第一轮先取离 Held 目标最近者，后续超出 `±20` 时利用归一化的上轮候选轨迹重新配对。能力页直接识别到闪光，或候选中已经包含目标 Held/Pickup 组合时，立即判定成功。

领取后 Seed 复核结束时角色仍在野生宝可梦能力页。旧骑车入口只按 3 次 `B`，前两次各等待 500 ms；实机出现过后续 `B` 被退页转场吞掉，紧接着的地图校正 `UP 200` 便作用在宝可梦操作菜单上，把光标从 `SUMMARY` 绕到 `CANCEL`。运行副本现在先按 5 次间隔 1500 ms 的 `B`，逐层退出能力页、操作菜单、队伍页和主菜单；多余的 `B` 在野外无副作用。开始骑车前会打印 5 段退出进度，骑车期间每 10 圈打印一次进度。

孵蛋页使用共享38步函数，定点波克比单独使用14步循环 `LS UP → 1300 → LS RESET → WAIT 300 → LS DOWN → 1300 → LS RESET`，两者不再共用骑车实现。孵蛋页与定点波克比都不读取 `蛋孵化` 标签，并保留原固定收尾 `WAIT 500 → B → WAIT 12000 → B → WAIT 1500 → B → WAIT 1500`；定点波克比仍保留自己的领取对话、F2 时间点和上车路线。

孵化后的能力页导航也复用普通反查的队伍页选择函数：普通定点的新入队目标从队首向上 2 次，孵蛋正式轮的蛋在第 5 位、后面还有第 6 位复核野生，因此传入 3 次，只多一次 `UP`。能力读取和 IV 范围继续复用通用识图链；孵蛋吃糖后改用第 5 位专用导航重新识图，避免误读第 6 位复核野生。多次升级得到的合法 IV 范围会逐项取交集，再交给蛋候选扫描，避免只使用最后一级的宽范围；多个候选只有在六项 IV 全部一致时才可停止喂糖并进入轨迹校准。蛋的候选计算仍必须使用 Egg 的 Split/Normal/Alternate/Mixed，不能替换成普通 Method 1/2/4。

野生 PID 循环上限为 200：保留已实机遇到的超过 100 次的长尾情况，同时避免 1000 次上限在完整 Wild1/Wild2/Wild4 反查中造成过长的无候选扫描。

两次野生 Seed 反查都按“刚捕获的宝可梦位于当前队伍末位”处理，从队首向上按 2 次；正式轮先领蛋到第 5 位，再抓复核野生到第 6 位，因此之后的蛋个体反查固定选择第 5 位并向上按 3 次。首次打开能力页和后续使用神奇糖果采用同一规则。

### 脚本测试（高级）

1. 在 EasyCon 共通设置中勾选“高级模式（直接脚本页；所有指纹仅警告）”。
2. 打开新增的“脚本测试（高级）”页，选择一个 `.ecs`。脚本同目录可带自己的 `lib\` 和 `ImgLabel\`。
3. 选择“工具兼容运行器（正式工具）”复现本工具的实际执行环境，或选择“原始 EasyCon 1.6.4-a CLI（A/B 对照）”排查兼容运行器差异。
4. 点击“预检所选脚本”。工具仍要求原始 `ezcon.exe` 返回正式支持的 `1.6.4-a+9c86137` 版本，执行真实 `format`，并核对主脚本与 `lib` 中直接出现的 `@标签` 是否存在；已登记文件的哈希不一致会显示“高级模式指纹警告”，但不阻止开始。
5. 运行输出保存为 `runtime/script_tests/logs/script-test-compat-日期_时间.log` 或 `script-test-original-日期_时间.log`，结束后也会回显日志尾部；同名 `.json` 会记录脚本 SHA-256、后端、执行文件和设备参数，方便确认 A/B 确实使用同一份脚本。

该页不会搜索方案、替换参数、复制所选脚本或套用 1.1.8 完整语料指纹，因此可以把同一个测试工程分别交给两种后端。日志包装器只负责原样转存终端输出；串口、采集卡、DSHOW 和 `build_run_command()` 与正式工具共用。页面还提供“准备内置冲浪结束测试”，会把仓库内置的 `冲浪.IL` 复制到独立运行目录；脚本等待 `冲浪 > 95` 后只按一次 `X` 并停住供人工确认，不发送方向键、抓捕或存档。

高级模式的指纹放宽同时作用于普通/孵蛋、TID、SID、直接脚本测试、兼容运行器准备和 Seed 更新时使用的 EasyCon 指纹。它只放宽 SHA/语料指纹不一致；文件或标签缺失、标签数量/方法分布异常、损坏的 Seed 表、EasyCon 版本不受支持以及 ECS `format` 失败仍会阻止启动。高级模式也不是安全沙箱：所选 ECS 仍拥有完整手柄控制权限。运行前必须人工阅读脚本并确认游戏位置与存档状态；A/B 结果只证明该测试脚本和当次采集环境的行为，不代表正式长跑已验收。

“监视窗口”在兼容运行器执行普通、孵蛋、TID、SID查找和连续御三家脚本期间均可打开。运行中读取 EasyCon 已采集画面的本机共享预览，不会再次占用采集卡，也不发送手柄输入；多阶段共用同一预览地址，阶段切换/生成计划期间可能短暂断流，窗口会自动重连。尚未运行脚本时，监视窗口才直接打开所选采集卡；原始164a CLI高级测试没有共享预览，运行期间仍不能另开监视。虚拟手柄、设备选择和高级模式在运行期间保持锁定。

### SID 查找

1. 把用于反查的闪光宝可梦依次放到队伍前 N 位，背包第一页第一格放神奇糖果，并在游戏内保存。
2. 在第一页填写游戏、主机、当前 TID、队伍数量、每只最多糖果和识图阈值。
3. 选择闪光宝可梦数量后，多余队伍行会自动变灰。每个活动槽位可选择或输入中文名、英文名，也兼容 `1-386` 的全国图鉴编号；还要填写当前存档内的初始等级、定点/野生来源和野生相遇地点。努力值按 HP、攻击、防御、特攻、特防、速度六列分别填写。名称会由 Python 转成图鉴编号，并把完整第三世代种族值和性别阈值写入脚本；摘要页名称与等级 OCR 均不用于正式判定，喂糖后的等级按成功次数递增。
4. 点击“准备 SID 查找”生成采集脚本并预检，再点击“开始运行”。程序会逐只采集，PSV 唯一时提前结束，并把报告回显到结果区。

SID 采集的原始输出会逐行实时写入 `runtime/sid_reverse/sid-reverse-*.log`，运行中同步回显到主界面。即使点击停止或 EasyCon 在重试中被取消，已经产生的输出也不会再被空文件覆盖；失败退出时结果区会显示去除 ANSI 颜色控制码后的日志尾部和失败阶段说明。摘要页首次识别失败会自动重新启动，最多尝试 3 轮，不应在刚出现 `ATTEMPT_RETRY` 时把它误判为无响应。

SID 每轮关闭游戏后不再使用固定的 `A → 1200 ms → A` 启动。生成副本先按所选 Switch 机型执行 HOME_BUFFER；默认仍严格要求 95 分，只有公共自适应开关开启时才允许连续 3 次稳定且唯一最高的 90–94 分标签降低本次阈值。HOME_BUFFER 命中后按 `A` 回到游戏，并从原来的 `WAIT 8000` 开始继续跳 OP 动画、进入存档和采集流程。

闪光公式只能确定 `TID xor SID` 的高 13 位，因此结果会列出 8 个真实 SID 候选；若其中某个候选出现在 TID/SID 1.3.7 建档生成链前 10000 ADV，工具再选择窗口内最早值，否则不会擅自选定。只支持第三世代 Method 1/2/4；孵蛋来源及其他生成方式暂不支持。原命令行入口 `启动-SID反查.bat` 仍可使用。

### TID 乱数

TID/SID 页使用“自定义TID SID 御三家乱数多功能包1.3”中的英文/日文 1.3.7 脚本。页面支持：

- 乱数模式或穷举模式；
- 目标 TID/SID、主角性别和名称；
- OP/F1/F2 中心帧、乱数半径、穷举起点和最大范围；
- OP/F1/F2/F3 固定延迟和固定延迟检查；检测完成后自动回填、重新生成并预检，再自动执行正式计划，手动编辑开关默认关闭；
- 豹子号、升/降连号、65535 和个位数 TID；
- SID 处理可选择“目标 SID（自动计算 ADV）”或“不乱数 SID（固定 F3，采用实际 SID）”；随机 F3 模式已经移除。乱数模式也可以采用固定 F3，由实际 TID 生成链决定 SID；目标 SID搜索不会再停在旧的 10,000 ADV窗口，默认最多检查前 1,000,000 ADV。
- TID 页提供“6V闪SID”：按当前 TID 和默认 PID `7942EF72`，搜索下限至少为 F3 固定延迟换算帧，并计入当前语言脚本的 SID 前置补偿及 SID ADV 修正；在前 1,000,000 ADV 上限内选择最早可执行的合法闪光 SID并回填目标 SID。开启高级模式后可编辑 PID；普通模式会强制恢复默认 PID。
- 可选的英文版 TID 到御三家连续流程：目标 TID/SID 乱数维持预先搜索与 SID ADV 重试；选择不乱数 SID时，第一阶段命中 TID 后读取实际 SID ADV，计算实际 SID，再动态搜索御三家；穷举模式同样在命中启用的 TID 条件后读取实际身份。Seed 时间直接取 Ten Lines 对应设置的 Seed 表，不要求用户填写时间下限。

脚本会新建存档并自动退出游戏两次。名称或性别改变后应勾选“先检测固定延迟，完成后自动运行计划”。单独TID与英文连续御三家均支持：第0阶段检测完整 OP/F1/F2/F3 和实际OP修正，工具自动回填并关闭检测；后台在新目录生成正式脚本，真实164a预检通过后自动执行，无需第二次点击开始。取消、异常或测量缺项时不回填、不继续；完整测量后若新计划预检失败，则保留测量结果并停止。若检测期间用户修改了界面，后台仍使用启动时的计划快照，不覆盖新输入。

结果保存在本次日志旁的 `.calibration.json`，新计划保存在同目录的 `tid-calibrated-*`，原生成工程不覆盖。后台衔接不依赖主窗口存活；TID实测表在正式阶段开始前切换到新测量参数，继续区分游戏与机型。四项输入仍默认不可手动编辑。日文旧1.3.7取名循环的164a兼容修正仍只作用于生成副本。

想快速获取御三家闪光而不挑号码：选择“穷举模式”，启用御三家计划，再勾选“取得任意 TID 后继续”。此时目标TID与特殊号码输入变灰，首次符合识别要求的实际TID即可用于计算SID、搜索御三家；目标TID不再作为成功条件。“任意 TID 等待去噪确认”默认开启，使用原去噪次数/窗口；关闭后首个完整、合法的TID即接续，不等待重复命中。两种方式都拒绝缺位及超出0–65535的识别结果。此开关不改变普通指定TID模式的去噪行为；关闭去噪会降低对偶发误识别的保护。

英文 1.3.7 默认在用户区结束标记之后保持与原版逐字一致；只有显式开启 HOME_BUFFER 稳定低分自适应时，生成副本才加入状态分类器并替换该阶段函数，原始模板不改。TID 与 SID 分类器只读取所选 Switch 机型的 `HOME_BUFFER正确退出`、`正确退出` 和 `错误退出` 标签，不降低其他阶段阈值。EasyCon 1.6.4-a GUI 会持续读取采集卡并对 ImgLabel 置信度使用 `Math.Ceiling`；同包 `ezcon.exe run` 只在每次标签求值时读一帧，且直接截断小数，DSHOW 缓冲帧可导致 CLI 在同一延迟看到旧画面。自动启动使用由同一 `9c86137` 源码构建的兼容 runner：后台持续清空采集队列，图片标签与本地 Tesseract OCR 共用最新帧副本，并保留 GUI 的向上取整。runner 使用自包含文件夹发布，避免 Tesseract 在单文件发布中无法定位原生库。启动时会输出采集卡返回的实际宽高。原始 `ezcon.exe` 仍负责版本/哈希、设备、Tessdata 与 `format` 预检，视频后端仍为 DSHOW。

TID 到御三家的连续流程不再复制样本中的旧御三家控制器。`automation/tid_starter_flow.py` 生成一份英文 1.3.7 ID 工程、独立研究所桥接工程，并复用现有 1.1.8 `Starter` 作为第三阶段；`run_tid_starter_flow.py` 在每一段成功退出后才启动下一段。目标 TID/SID 乱数仍在开始前生成第三阶段。穷举模式的五种原成功条件或可选的“任意TID”条件输出实际五位 TID 和 SID ADV；Python 按 1.3.7 的“第一次 LCG 结果为 ADV 0”约定计算实际 SID，之后才从指定 ADV 范围搜索最早可达的闪光 Method 1 御三家、生成第三阶段并执行真实 1.6.4-a 预检。日文 1.3.7 仍可单独运行，但现有 1.1.8 的 Seed 表和 OCR 只审计了英文版，因此暂不开放日文连续流程。

御三家阶段完全复用 1.1.8：领取御三家、打开能力页、读取个体、反查和 Seed/帧校准均由原流程负责。1.1.8 输出“已识别到出闪，脚本停止”时连续流程结束。目标 TID/SID 乱数若精确命中 PID 但不闪，仍按 `$SID_ADV修正` 的 `当前、+1、-1、+2、-2...` 顺序重新执行三段；穷举模式使用本轮实际身份，不套用这组目标 SID 重试，若精确 PID 不闪则保留日志停止。GUI 的穷举计划先生成 `01_id`、`02_lab_bridge` 和 `flow_plan.json`，`03_starter_118` 在实际身份确定后生成并预检。代码链已接通，仍需 Switch 实机验收动态衔接、研究所路线和目标 SID 重试。

### TID 实测表

先在“TID 乱数”的基本条件中选择实际的游戏版本和 Switch 机型，再生成并运行。游戏选择在关闭御三家连续流程时也可使用；分类以本次启动时的选择为准，不是自动识别游戏。

第三页“TID 实测表”自动收集工具启动的 TID 单独运行或连续流程第一阶段中的有效观测。记录实际 TID、OP/F1/F2、SELECT 次数、主角/语言/按键设置、固定延迟及实际 OP 修正。同一号码在不同游戏、机型或参数下分开统计；“出现次数”是收到的完整观测数，不是脚本去噪窗口的累计数，也不代表再次运行保证命中。表中不记录 SID、SID ADV 和 F3，不改变原脚本操作流程。

r3 的实际 OP 机型补偿也会记入详情和 CSV：新版 NS2 的 −750ms 与旧版 NS2 的零补偿记录分开统计；NS1 零补偿继续兼容原记录，不清空旧表。

可按游戏、机型及完整 TID 查询（TID 留空为全部），选择记录查看详细设置，或导出带 UTF-8 BOM 的 CSV。界面最多显示最近 1000 项参数记录，CSV 包含当前筛选的全部结果。记录由运行器保存，即使关闭主窗口并保留运行器继续运行，仍会积累；本次更新前已启动的进程和旧日志不会自动补录，高级页直接运行的任意脚本也不会自动记入。

数据保存在 `%LOCALAPPDATA%\FRLG-Auto-RNG\tid_records.sqlite3`，源码版与新版绿色版共用。跨设备保留记录时，先停止所有运行器，再复制此文件到新设备的同一路径；CSV 用于查看/分享，本版不提供 CSV 导入或一键回填参数。

## 命令行计划器

只生成计划、不启动硬件：

```powershell
.\.venv\Scripts\python.exe run_auto_planner.py `
  --game fr_nx --tid 58888 --sid 12232 `
  --method Static --category Starter --pokemon Bulbasaur `
  --max-advances 100000 `
  --iv-min 29/31/27/29/29/30 `
  --iv-max 29/31/27/29/29/30
```

只有显式增加 `--run` 才会把控制权交给兼容 runner。换设备后必须复制完整的 `runtime_backend` runner 文件夹；若缺失，可运行 `tools\build_easycon164a_compat_runner.ps1` 重新构建。
