# 单片机自动连接

## 用户操作

顶部新增“自动连接”，普通模式也能用。它与“重新检测”不同：检测只列出串口；自动连接会向串口发送伊机控的 Hello 握手，收到正确回复才认定为单片机。

1. 插好 USB / TTL 线并确认单片机已烧录兼容固件。
2. 点“自动连接”：先试当前选择，再按自然序尝试其他串口（USB/普通串口优先，蓝牙后试）。成功后自动选中真正连接到的 COM。
3. 连接中按钮为“取消连接”；成功后为“断开单片机”。想重查时先断开再点自动连接。
4. 虚拟手柄沿用所选串口，不会悄悄改试另一只设备。需要自动查找时使用自动连接按钮。

成功串口保存在 `pyside6_settings.json` 的 `preferred_controller_port`；重开后，设备检测优先恢复仍在线的成功串口。当前在线选择优先保留。启动检测不会自行握手或长期占用串口，自动连接也不启用手柄键盘控制；明确打开虚拟手柄后才启用。连接在脚本启动前释放，既有运行器再按原流程接管，不改变 ECS 按键、Seed、帧数或唤醒流程。小窗口将设备按钮独立换行，避免与高级模式/设置重叠。

失败会显示当前端口/波特率和握手、超时或驱动报错，并提示检查 USB/TTL、固件、驱动和其他伊机控/串口程序占用。没有通过握手的端口不能标为已连接。若 USB 重插后连接已失效，再点自动连接会先清理失效连接再重新查找。

## 与伊机控对齐的依据

对照仓库本机固定源码 `9c86137c7e63bff842175470895727a5fa9bab52`，没有升级到170：

- `src/EasyCon2/Services/DeviceService.cs` 的 `AutoConnectAsync`：后台逐端口尝试，第一只成功即选中；手动连接只试指定端口。
- `src/EasyCon.Device/JoyStickDevice.cs` 的 `TryConnect`：115200失败后等待100ms，再回退9600；工具中的这段等待也能取消。
- `src/EasyCon.Device/NintendoSwitchCmd.cs` 的 `_TryConnect`：每次连接等待1000ms。
- `src/EasyCon.Device/Connection/TTLSerialClient.cs`：`Ready → Ready → Hello`，检查回复首字节为 `Reply.Hello`。

工具按同一协议和波特率顺序实现。USB优先、当前端口优先和成功串口记忆是工具侧优化；不复制每个失败端口额外等待一秒，因为临时句柄正常关闭完成后才继续。DTR/RTS在打开前置低，保留对CH340/Arduino兼容板的防复位处理。移除原Python路径额外尝试的57600/38400/19200，避免工具声称连接成功却不属于固定164a运行器支持的连接速度。

## 取消和生命周期保护

新 `easycon/serial_connection.py` 将临时串口归连接探测线程所有，控制器仅接纳按时、未取消且经过握手的结果。每次探测按单调时钟限制为一秒；不是原来的两轮握手加额外长等待。Windows驱动内部阻塞不能强制中断，调用方可超时/取消，迟到线程返回后自行关闭句柄；同一尚未释放的端口不并发重开，不把迟到成功接入控制器。

切换串口、关闭浮窗、退出工具或开始脚本均通过原串口归属链处理。自动连接过程中参数选择变动会取消原尝试，迟到结果不抢回旧选择。运行/预检期间不启动自动连接；连接中不允许启动脚本。只连接不发送游戏按钮，未发送的旧按键状态在断开时清理。主窗口销毁后不再更新它的UI。

## 验证范围

测试使用假串口与离屏完整PySide6界面，覆盖握手格式、首字节判断、波特率回退、超时、取消、迟到句柄释放、端口切换、运行交接、窗口销毁和成功串口重开记忆。没有枚举/连接真实串口，没有发送Switch按键。源码重启生效；本轮不改母本、不打包、不发布Release。

完整回归1020项通过（584.454秒）；最终窗口复用修复另复测串口16项、GUI连接9项及既有手柄26项，旧路径/配置恢复10项也通过。固定发布运行器16项输入协议样本及mock HTTP、PRINT与GUI检查通过，Python编译、空白检查及Windows无设备界面截图通过。离屏布局回归确认900/1180/1360宽度下设备按钮不重叠，另用Windows900宽度截图确认实际布局；不将这些结果当作实机连接验收。
