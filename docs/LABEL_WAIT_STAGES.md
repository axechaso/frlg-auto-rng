# 标签等待阶段与故障恢复

状态记录：2026-09-25。本文描述本轮代码覆盖范围；阶段预算仍需连接 Switch 后按实际运行验证。

## 已接入的监督闭环

该闭环是用户主动启用的保护功能。PySide6 顶部提供“标签故障保护”开关，默认关闭并保存用户选择。关闭时兼容运行器不创建阶段监督器、不锁定手柄，也不保存故障事件；原脚本继续按既有行为运行。开启后才执行下述监督与故障资料采集。原始 EasyCon 1.6.4-a A/B 后端不支持该开关。

工具兼容运行器从 ECS 日志读取 FRLG_STAGE 事件，并在活动阶段内独立检查：

- 采集设备是否报错，最新画面是否持续更新；
- 当前阶段登记的标签组、比较符、阈值和实测分数；
- 阶段从上次有效推进开始经过的时间；
- ECS 显式发出的失败出口。

监督器只把标签条件当作阶段上下文，不把任意低分当成错误。超时或脚本失败时，它会取消脚本、阻断后续手柄输入、释放并归中手柄，保存采集源的原分辨率帧及本次实际加载的标签、运行参数、标签分数和日志。应用以退出码 20 将事件传给 PySide6；事件卡片提供截图和“重做此标签”入口。

阶段事件包括：

| 事件 | 用途 |
| --- | --- |
| BEGIN | 登记阶段、重试组、预算、调用位置、恢复方式和 OR/AND 标签条件。 |
| END | 成功离开阶段并清除本阶段帧与重试计时。 |
| PROGRESS | 只在业务状态确实前进时重置重试组计时和分数窗口。 |
| THRESHOLD | 更新自适应 HOME_BUFFER 阶段的实际阈值。 |
| FAIL | 让 ECS 已有重试上限直接结束本次运行并生成故障事件。 |

timeout_ms=0 表示阶段本身有脚本内重试上限，由 FAIL 报告上限耗尽；采集失效监督仍持续生效。这样不会在有界校准尚未走完时先被墙钟超时打断。无界的关闭动画等待使用正数预算。

## 标签重制与生效

PySide6 故障卡片从运行器事件读取原图、阶段和当次标签。修复页在窗口中载入原标签和搜索设置；框选、方法选择、离线测试和动态测试调用固定 1.6.4-a 运行器的原生 ImgLabel.Search()，测试分数按运行器 Math.Ceiling 规则计算。

动态测试由正在运行的兼容运行器继续拥有采集设备，采集三张新帧并分别留存原始 PNG；可额外测试相邻画面。它不会另开一个采集对象争抢同一张采集卡。

“保存并用于当前设备”按设备名写同名标签覆盖和修改历史，先验证文件和原语料方法，再原子更新登记；保存失败时恢复上一版。若当前仍有已选搜索结果，工具以原 PlanSearchResult 重建运行工程并执行正常预检，不重新搜索目标；记录新生成目录和应用状态。回滚会恢复所选历史版本并要求重新生成工程。

故障资料保存到 %LOCALAPPDATA%/FRLG-Auto-RNG/label_incidents/。设备覆盖保存到同一用户目录的 device_label_overrides/。清除覆盖不会修改原始 .IL 包。

## 验收状态与未覆盖事项

本地 Python 检查、固定 EasyCon 1.6.4-a 的 format 和工具兼容运行器构建可证明代码结构与版本一致，不能证明某个预算适合实际游戏节奏，也不能代替 Switch 画面验收。

当前改动覆盖抓捕、狩猎区、名称 / 未知图腾形态、性别 / 性格 / 等级 / 能力值回退、主脚本设置和 HOME_BUFFER 校准、日版御三家读取、TID、SID，以及孵蛋关闭 / 设置 / 池塘阶段中的已核实阻塞点。HOME_BUFFER、名称和数字候选使用脚本现有上限并显式上报；合法的 RNG、帧校准、孵化、钓鱼未咬钩和路线等待仍保留原语义。高级模式用户自行组合的任意 ECS 不会自动获得完整阶段登记，需按同一协议逐项接入。

静态核对覆盖正式版 / 时间轴版入口、TID/SID 采集与球前存档入口及顶层库脚本，共 34 份 ECS；其中有 85 个阶段声明、1,030 个标签候选引用，均能在当前 1,151 个标签中找到对应 `.IL`。这验证了登记名和资源存在，不代表标签框选正确或实机分数达标。

为保持仓库现有镜像一致性检查，两个 170a 实验镜像也同步了日版识别失败出口；它们仍不属于正式目标运行时，也不因此获得正式支持结论。
