# 无存档自动建档：独立实机测试

日期：2026-10-05。仅测试准备基础游戏存档，尚未接入正式 TID 页或正式母本。不要把本测试的临时身份或 OP 等待直接回填为目标乱数参数。

## 从哪里运行

测试入口已复制到用户当前原包根目录：

`D:\Download\NS火叶全自动一键乱数1.1.8\无存档自动建档-164a测试.ecs`

用 EasyCon **1.6.4-a+9c86137** 打开这份 ECS。它必须与最新 `ImgLabel` 文件夹同级，其中包含用户新增的 `无存档.IL`。工具仓库可追踪的原始测试文件在 `assets/tid_rng137_tests/无存档自动建档-164a测试.ecs`；不修改导入缓存或已有运行工程。

启动前：

1. 连接单片机和视频源，采集画面使用 1920×1080。
2. NS 主页选中需要测试的火红/叶绿，**游戏已经关闭**。
3. 选用确实没有存档的游戏用户/测试环境；不要为了测试删除已有存档。
4. 脚本默认美版、NS1、男主角。日版将 `$测试ROM语言` 改为 `1`；语言和 NS 机型互不替代，NS1 仍填 `1`。

本测试会真实执行新游戏和保存操作，不是纯识图回放。自动化离线检查不访问控制器、采集卡或 Switch。

## 你会看到什么

1. 唤醒单片机，确认 NS 主页且游戏已关闭，再建立 HOME_BUFFER。
2. 按 OP 键后，在原母本的释放后 400/450/500 ms 窗口读取 `存档` 和 `无存档`。固定门槛 **95**，日美版共用这两个标签，没有低分自适应。
3. 只有无存档通过时，不按有存档流程的 DOWN，直接确认 NEW GAME。
4. 沿用 TID 母本开场 A/B 对话顺序，保留日版额外两次 B 和最后一次 A；主角与劲敌均选择第一个预设姓名，不进入自定义姓名键盘。
5. 进入房间后，打开 OPTION，用所选语言的 FAST/MID/SLOW 标签选唯一最高分。MID 向右一次，SLOW 向左一次；FAST 再次达到 95 后才允许保存。
6. 从 OPTION 返回菜单，向上一项选择 SAVE，执行首次保存并等待写入。声音、战斗动画、按键模式不修改。
7. 默认自动重启，重新在 OP 后检查已有存档入口。确认后停在标题菜单，不进正式乱数、不领取御三家、不登记工具中的存档资料。

判断表：

| `存档` | `无存档` | 测试动作 |
| --- | --- | --- |
| ≥95 | <95 | 已有存档，停止，不开始新游戏 |
| <95 | ≥95 | 仅无存档确认，允许建档 |
| <95 | <95 | 按 OP 过早处理，增加等待 50 ms 并重开 |
| ≥95 | ≥95 | 冲突，保留现场停止，不猜测 |

OP 最多自动增加 10 次（500 ms）；达到上限后不再重启。重启检查时若仍无存档或状态冲突，只报告验证失败，**不会回头再建一遍**。语速识别/设置失败时不保存、不重启，保留现场。

## 可改的测试参数

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `$测试ROM语言` | `0` | 0=美版英文，1=日版；火红/叶绿共用 |
| `$测试NS机型` | `1` | 1=NS1，2=NS2；只在显式选 NS2 时扣 750 ms |
| `$测试主角性别` | `0` | 0=男，1=女；使用预设姓名 |
| `$测试OP基础等待MS` | `30600` | 本测试的固定等待毫秒，不是 ADV，也不是完整 TID 计划的回填值 |
| `$测试OP初始修正MS` | `0` | 本测试额外等待；只影响本次运行 |
| `$测试OP按键` | `0` | 0=A，1=X（游戏 Start），2=L |
| `$测试HOME_BUFFER延迟MS` | `1200` | 初始 HOME_BUFFER 等待，试探有次数/范围上限 |
| `$测试关闭等待MS` | `1500` | NS 主页/关闭等待 |
| `$测试建档后重启验证` | `1` | 改为 0 时保存按键后直接停止，供人工观察，不宣称保存成功 |

## 卡住时给什么资料

保留从测试开头到停止的完整日志和最后画面。阶段文本是“启动及 OP / 创建新游戏 / 语速设置 / 首次保存 / 重启检查”；创建内部另有对话、性别、主角预设名、劲敌预设名四个进度点。

- `BOOTSTRAP_OP`：语言共用的两标签分数、采样编号和状态。
- `BOOTSTRAP_TEXT`：语言、FAST/MID/SLOW 的分数和最高分判定。
- `BOOTSTRAP_HOME_BUFFER`：本次等待和三类 NS 退出分数。
- `BOOTSTRAP_HOME_FAIL / BOOTSTRAP_CLOSE_FAIL`：停止时的启动/关闭证据。

首次保存与覆盖不同存档的确认不同，本测试没有发送后者使用的“向上选择 YES”。保存后重启才用于确认已有存档入口；仅按键完成不算已证明保存成功。首次保存分支和初期菜单排列核对来源：[pokefirered 的菜单与保存实现](https://github.com/pret/pokefirered/blob/master/src/start_menu.c)。开场等待来自用户当前 TID 母本，预设名字选择和实际菜单落点仍须分别在美版/日版实测。
