# 无存档自动建档：独立实机测试

更新日期：2026-10-07。仅测试准备基础游戏存档，尚未接入正式 TID 页或正式母本。不要把本测试的临时身份或 OP 等待直接回填为目标乱数参数。

## 从哪里运行

测试入口已复制到用户当前原包根目录：

`D:\Download\NS火叶全自动一键乱数1.1.8\无存档自动建档-164a测试.ecs`

用 EasyCon **1.6.4-a+9c86137** 打开这份 ECS。它必须与最新 `ImgLabel` 文件夹同级，其中包含用户新增的 `无存档.IL`。工具仓库可追踪的原始测试文件在 `assets/tid_rng137_tests/无存档自动建档-164a测试.ecs`；不修改导入缓存或已有运行工程。

启动前：

1. 连接单片机和视频源，采集画面使用 1920×1080。
2. NS 主页选中需要测试的火红/叶绿，**游戏已经关闭**。
3. 选用确实没有存档的游戏用户/测试环境；不要为了测试删除已有存档。
4. 仓库默认美版、NS1、男主角；当前原包实测文件保留用户设置的日版、NS1、女主角。美版填 `$测试ROM语言 = 0`，日版填 `1`；该项只选择语速标签，不再改变建档按键和等待。语言和NS机型互不替代，NS1仍填 `1`。

本测试会真实执行新游戏和保存操作，不是纯识图回放。自动化离线检查不访问控制器、采集卡或 Switch。

## 你会看到什么

1. 唤醒单片机，确认 NS 主页且游戏已关闭，再建立 HOME_BUFFER。
2. 按 OP 键后，在原母本的释放后 400/450/500 ms 窗口读取 `存档` 和 `无存档`。固定门槛 **95**，日美版共用这两个标签，没有低分自适应。
3. 只有无存档通过时，不按有存档流程的 DOWN，直接确认 NEW GAME。
4. 使用用户最新实测流程：大木博士35次B、每次WAIT 800，随后日美共同保留2次B（每次按下50ms、等待3000ms）。主角使用空白默认名，`X → WAIT 500 → A → WAIT 4000 → A` 提交并确认，然后14次B；劲敌选择第一项预设名并推进20次B。创建段不随ROM语言分岔，所有已成功的等待和按键保持。仓库副本已同步这一操作段，与外部文件只差两项个人配置。
5. 进入房间后，打开 OPTION，用所选语言的 FAST/MID/SLOW 标签选唯一最高分。MID 向右一次，SLOW 向左一次；FAST 再次达到 95 后才允许保存。
6. 从 OPTION 返回菜单，向上一项选择 SAVE，执行首次保存并等待写入。声音、战斗动画、按键模式不修改。
7. 默认自动重启，重新在 OP 后检查已有存档入口。确认后停在标题菜单，不进正式乱数、不领取御三家、不登记工具中的存档资料。

判断表：

| `存档` | `无存档` | 测试动作 |
| --- | --- | --- |
| ≥95 | <95 | 已有存档，停止，不开始新游戏 |
| <95 | ≥95 | 仅无存档确认，允许建档 |
| <95 | <95 | 按 OP 过早处理，增加等待 50 ms 并重开 |
| ≥95 | ≥95 | 冲突，保留现场停止，不猜测 |

OP 最多自动增加 10 次（500 ms）；达到上限后不再重启。重启检查时若仍无存档或状态冲突，只报告验证失败，**不会回头再建一遍**。语速识别/设置失败时不保存、不重启，保留现场。

## 可改的测试参数

| 参数 | 仓库默认值 | 用途 |
| --- | --- | --- |
| `$测试ROM语言` | `0` | 0=美版英文语速标签，1=日版语速标签；建档按键/等待日美共用 |
| `$测试NS机型` | `1` | 1=NS1，2=NS2；只在显式选 NS2 时扣 750 ms |
| `$测试主角性别` | `0` | 0=男，1=女；主角使用空白默认名，劲敌选第一项预设名 |
| `$测试OP基础等待MS` | `30600` | 本测试的固定等待毫秒，不是 ADV，也不是完整 TID 计划的回填值 |
| `$测试OP初始修正MS` | `0` | 本测试额外等待；只影响本次运行 |
| `$测试OP按键` | `0` | 0=A，1=X（游戏 Start），2=L |
| `$测试HOME_BUFFER延迟MS` | `1200` | 初始 HOME_BUFFER 等待，试探有次数/范围上限 |
| `$测试关闭等待MS` | `1500` | NS 主页/关闭等待 |
| `$测试建档后重启验证` | `1` | 改为 0 时保存按键后直接停止，供人工观察，不宣称保存成功 |

## 卡住时给什么资料

大木博士公共对话段按用户最新实测调整为 `FOR 35`，每次B后 `WAIT 800`；累计800ms等待为28秒，不包含B命令自身的按下时长。后面2次B的等待现在日美均执行，不再因为选美版少掉6100ms显式等待。修改ROM语言不会再改变性别/取名/入房间动作；请按实际游戏选择语速标签语言。

主角空白取名的 `X（游戏Start）→ 等待 → A` 提交默认姓名，回到“这个名字对吗？”还需A确认YES；最新实测段已经保留了这个额外A，再开始14次B。此前“主角选择列表第一项预设名”的说明不准确，主角会直接进入取名键盘。核对来源：[取名键盘](https://github.com/pret/pokefirered/blob/master/src/naming_screen.c)、[大木开场及姓名确认](https://github.com/pret/pokefirered/blob/master/src/oak_speech.c)。

保留从测试开头到停止的完整日志和最后画面。阶段文本是“启动及OP / 创建新游戏 / 语速设置 / 首次保存 / 重启检查”；创建内部另有对话、性别、主角默认名、劲敌预设名四个进度点。

- `BOOTSTRAP_OP`：语言共用的两标签分数、采样编号和状态。
- `BOOTSTRAP_TEXT`：语言、FAST/MID/SLOW 的分数和最高分判定。
- `BOOTSTRAP_HOME_BUFFER`：本次等待和三类 NS 退出分数。
- `BOOTSTRAP_HOME_FAIL / BOOTSTRAP_CLOSE_FAIL`：停止时的启动/关闭证据。

首次保存与覆盖不同存档的确认不同，本测试没有发送后者使用的“向上选择YES”。保存后重启才用于确认已有存档入口；仅按键完成不算已证明保存成功。首次保存分支和初期菜单排列核对来源：[pokefirered的菜单与保存实现](https://github.com/pret/pokefirered/blob/master/src/start_menu.c)。最新建档动作来自用户当前成功的测试文件，修改后美版配置的完整流程仍须实机复测。
