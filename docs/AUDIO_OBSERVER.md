# 声音判闪试用

这是供人工对照的声音观察功能。监听采集卡的游戏音频，匹配到疑似闪光出场音效后，在运行日志显示一行提示，并保存独立的观察日志。它不会停止任务、操作手柄、改变现有判闪结果、触发声音专用 QQ 通知或推进任何自动流程。

## 开始试用

1. 打开正式 PySide6 界面的“共通设置 → 声音判闪试用”。
2. 刷新音频设备，明确选择采集卡对应的音频输入，例如 USB Digital Audio。音频设备与视频设备分开选择；有画面不代表已有音频。
3. 默认相似度阈值为 `0.80`。点击“开始监听”，检查输入电平是否随游戏声音变化。数值越高越严格；相似度不是识别准确率。
4. 正常运行原有流程，或手动游玩，对照画面查看“运行日志”中的 `[声音观察]` 提示。收起窗口仍继续监听；“停止监听”或退出软件会结束监听。

每次启动软件都需要手动开始监听；只记住上次选择的设备和阈值，不会自动打开默认麦克风。声音仅在内存中用于匹配，不保存连续录音，也不播放或上传音频。音频设备断开、采集失败、持续断流或观察日志无法写入时，只停止声音监听，原有自动流程继续。

设备列表来自 Windows 暴露给 Qt 的音频输入端点。若采集卡只在 OBS 的专用采集路径中提供声音，需要先让游戏音频通过可选的录音端点输入；OBS 虚拟摄像头本身不携带音频。本功能不采集系统扬声器回环。

## 查看记录

提示示例（时间、分数和名称仅为示意）：

```text
[声音观察] 2026-10-02T20:15:30.123+08:00 疑似闪光音效；相似度=0.913；阈值=0.80；音源=采集卡游戏音频；第1次；声音窗口结束距今约0.20秒；运行日志=…；仅记录，不参与流程判断。
```

声音记录单独保存在 `%LOCALAPPDATA%\FRLG-Auto-RNG\logs\audio-observer\audio-observer-YYYY-MM-DD.log`，可在“历史日志”选择“声音观察”并刷新查看。不会写入用于检查点、预校准和命中解析的原始运行日志；运行期间的观察记录会附上对应运行日志路径，便于关联。时间是日志写入时间，声音窗口的延迟仅为估计，未做实卡声画延迟标定。

## 判断可靠性

当前使用一段火红 / 叶绿出场录音作频谱时序匹配，样本约 0.772 秒且含背景音乐。它可能受音乐、音量、采集卡处理及声道混合影响；不能区分敌我，也不会限定在哪个流程阶段监听。同一次声音会合并提示，之后有约 3 秒冷却，短时间连续声音可能只记一次。静音、没有提示或音频不可用均不代表“非闪光”。

试用时建议保留录像及声音观察日志，记录“画面确实出闪但没有提示”和“普通场景出现提示”的时间，并附上阈值、设备及游戏音量。先保持阈值固定收集一段时间，再根据误报、漏报情况调整。当前默认 `0.80` 尚未经过多场景标定。

已完成样本回放、音量变化、48 kHz 双声道转换、静音 / 噪声 / 单音负样本、模拟实时采集及流程隔离测试。原始录像同源回放只验证实现链路；尚未完成实际采集卡实时验收或独立样本准确率评估。
