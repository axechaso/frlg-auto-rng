# QQ 通知与接入教学界面方案

2026-09-20。设计预览已按本文件落地为原生 PySide6 实现；用户随后已确认真实 QQ 连接与收发正常，其他使用者仍需填写自己的机器人凭据和目标。

## 依据与范围

参考本机线程 01a0bc69-34ef-7701-b2c2-e8ec45831ce0 最新的 BDSP 集成，包括：

- notifications/qq_client.py：Qt 异步通信、绑定码倒计时与自动换码。
- notifications/qq_service.py：配置、通知队列、运行事件与投递记录。
- ui/qq_notifications.py、ui/qq_guide.py：原生设置窗口与复用表单的分步教学。
- docs/assets/guide-qq：12 步注册教学、原图、点击位置和局部取景。

本仓库之前导入的 tools/qq_notify_test 是较早的独立工具快照；正式界面使用 `notifications/qq_service.py` 和 `pyside_app/qq_notifications.py`，独立工具测试仍作为客户端协议回归。

## 入口与视觉

推荐在主界面顶部的存档、设备摘要附近增加“QQ 通知”按钮，展示一个简短的启用状态。所有工作区共享同一入口。共通设置中保留同一窗口的入口，便于首次配置。预览提供“仅收进共通设置”的备选，可比较主界面的密度。

正式窗口使用现有 ThemedDialog、APP_STYLE 和 Card：微软雅黑 UI、浅蓝灰背景、白色 14px 圆角卡片、蓝紫主操作按钮、细边框输入框。主界面的深色侧栏与页面结构沿用现状。无需增加一个新的业务侧栏页，也无需引入网页内核。

窗口建议初始约 900×760，适配当前项目的缩放与小屏策略。顶部标题、启用开关、页签和底部操作固定；内容区在空间不足时纵向滚动。双列内容在窄窗口改为单列，优先确保绑定码、操作按钮和错误文字可见。

## 设置窗口

| 页签 | 内容 |
|---|---|
| 接入设置 | 左侧凭据与接收方，右侧图文测试；首次进入可以直接打开教学 |
| 通知规则 | 任务结束、异常停止、手动停止三个开关，以及附图选项；右侧显示通知内容示例 |
| 发送记录 | 本次会话中的通知类型、时间、接收方、投递结果与失败详情 |

凭据区提供 AppID、带显示按钮的 AppSecret、验证按钮、验证状态。“记住密钥”默认关闭；开启时使用当前 Windows 账户加密保存。接收方通过验证码绑定，默认不要求填写 OpenID；私聊和群聊可同时选择，重新绑定入口保持可见。

首次配置时通知默认关闭，待用户验证后自行开启。预览使用“已绑定私聊”的示例状态，以便直接检查图文测试与消息样式；可在预览的设计选项中切换首次接入、等待绑定和投递失败。

图文测试固定发送说明文字与 FRLG 火稚鸡图标，提示用户在 QQ 中核对两者。接口提交成功和用户确认收件分开显示，按钮不会因一次文字成功就宣称整条图文链路通过。

## 教学流程

在同一设置窗口切换三个阶段：

1. **注册机器人**：复用 12 张原始教学截图，提供步骤列表、上一/下一步、操作区域/完整截图切换、点击位置提示。已有机器人可直接跳到连接阶段。教程文案中的软件名称和头像说明改为 FRLG。
2. **连接与绑定**：直接使用接入设置中的同一组凭据、接收方表单，无需来回切换或重复填写。60 秒倒计时逐秒更新；到期自动换码，旧码立即失效。取消、绑定成功和关闭窗口后停止刷新。
3. **图文验证**：复用图文测试面板，核对收件后开启通知。用户可随时返回设置，保留已经填写的状态。

教程打包为本地图片与数据，正式界面使用原生 Qt 显示。预览使用缩小后的图片呈现布局；正式实现应保留原图，以便放大检查。

## 事件与消息

默认通知任务结束和异常停止，手动停止默认不通知。任务结束须根据最终报告区分：

- 确认命中：流程、宝可梦、已确认的闪光/个体结果、关键 Seed/ADV 或 Held/Pickup 参数、耗时。
- 未确认命中：明确写明结果待确认、SID 候选未唯一或遍历耗尽等实际状态。
- 异常停止：流程、停止阶段、具体失败原因和耗时。

可选附带结束时可用的游戏画面；无可用画面时发送文字。软件图标只作为测试图片，不冒充实际游戏截图。图片不得来自重新独占采集卡；应复用监视服务已有的帧。

连续 TID → 御三家按整条流程通知一次，校准和内部重试不单独发送。不凭退出码 0 就宣称命中，也不把 Qt 工作线程完成、方案生成成功等内部事件当成任务结束。
