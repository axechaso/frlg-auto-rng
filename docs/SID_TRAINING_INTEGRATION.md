# SID 查找：战斗练级与努力值记录接入

日期：2026-10-07。

## 当前交付边界

本轮完成**参考脚本审计、Python 努力值账本、多观测反查和日志回放**；没有把原包直接接到正式自动运行按钮，也没有连接单片机、采集卡或 Switch。

正式 SID 查找页仍使用原来的神奇糖果采集。练级模式的 UI、日美版自动操作与识图生产端尚未接入，不能将下面的协议测试称为自动练级实机通过。旧 SID 遍历、糖果采集、2.0 母本及共同标签不改。

经验获取方式尚待用户选择：待反查宝可梦自己战斗、携带学习装置，或两种都支持。Python 账本已能表达两种接收方式，但这不代表对应的手柄流程已经实现。

- 英版经验处理含无限等待、连续按 B、默认允许进化、技能学习处理；不能原样作为珍贵闪光宝可梦的无人值守采集流程。

## 2. 已实现的数据链

`rng/ev_training.py`复用随工具携带的第三世代`personal_rsefrlg.bin`，按全国图鉴 1–386 读取各物种实际 EV 产出。界面顺序为 HP / 攻击 / 防御 / 特攻 / 特防 / 速度；总量接近上限时按游戏内部 HP / 攻击 / 防御 / 速度 / 特攻 / 特防顺序分配。

规则依据：[火红/叶绿 MonGainEVs](https://github.com/pret/pokefirered/blob/master/src/pokemon.c)、[战斗经验结算](https://github.com/pret/pokefirered/blob/master/src/battle_script_commands.c)、[第三世代物种 EV 数据](https://github.com/pret/pokefirered/blob/master/src/data/pokemon/species_info.h)。

- 每项上限 255，总量上限 510；精确计算剩余可获得量，不把 252 当作游戏硬上限。
- 三地鼠速度 2、火暴猴攻击 2、胖丁 HP 2。不能统一按“一只 1 点”。
- 曾感染病毒（含已痊愈）与强制锻炼器分别乘 2，可以叠乘。学习装置不把 EV 按经验比例分摊。
- 学习装置和强制锻炼器不能同时携带；中途换道具、染上病毒或更换接收方式必须结束当前会话并重新核对，不能沿用旧倍率。
- 未确认经验结算、待测宝可梦失去资格、逃跑/捕获/结果不明，不提交击倒。上游误报确认仍会污染结果；Python 无法凭一个文本标志证明真实画面，生产端必须另行验收。
- 每次观测携带自身 EV 快照，分别计算 IV 可行集合后逐项取交集，再复用现有 Method 1/2/4 PID 与 SID 反查。
- 普通日志中没有账本却变化的 EV 仍拒绝；不把旧遇敌计数或一个`TRAINING=1`开关当作凭据。
- 升级前已获得但尚未重算能力的 EV 不能直接套到旧能力值上。第一组采集初始状态，后续仅在确认升级并读取实际等级后采集；单次战斗升多级可以记录实际最终等级，不按“一次战斗 +1 级”猜测。
- 同时修复 IV 计算中“不可能的能力值被忽略”的情况：空可行集合应使反查失败，不应该继续输出貌似有效的结果。

## 3. 日志协议 v1（生产端待接入）

保留原`SIDREV|META|TID=...`。练级事件另用`SIDTRAIN`，不能混入原糖果的`ATTEMPT_BEGIN`自动重启语义。

```text
SIDREV|META|TID=12345
SIDTRAIN|BEGIN|V=1|SESSION=run1|MON=1|DEX=1|LEVEL=95|SOURCE=STATIC|LOCATION=|RECIPIENT=PARTICIPANT|MACHO_BRACE=0|POKERUS=0|EVHP=0|EVATK=0|EVDEF=0|EVSPA=0|EVSPD=0|EVSPE=0
SIDTRAIN|OBS|V=1|SESSION=run1|MON=1|SEQ=0|DEX=1|SOURCE=STATIC|LOCATION=|NATURE=0|LEVEL=95|RECALC=INITIAL|EVHP=0|EVATK=0|EVDEF=0|EVSPA=0|EVSPD=0|EVSPE=0|HP=219|ATK=127|DEF=127|SPA=128|SPD=157|SPE=119
SIDTRAIN|DEFEAT|V=1|SESSION=run1|MON=1|SEQ=1|FOE=16|RESULT=DEFEATED|XP_CONFIRMED=1|RECIPIENT_CONFIRMED=1
```

以上能力值只是协议示例，不代替用户宝可梦的实际观测。后续 OBS 的`SEQ`必须等于已确认击倒数，`RECALC=LEVEL_UP`，并携带与账本完全相符的六项 EV。来源与地点始终表示待反查宝可梦**原本取得的位置**，不是当前练级地点。

首组观测不能省略。重复/缺失/倒序击倒、跨槽位或跨会话、进化导致物种改变、身份信息变化、未知版本、重复字段、EV 快照不符或未重算能力均拒绝。可以重复读取同一等级同一击倒序号，以重试识图；新增击倒后的同等级旧能力不能采纳。

现有`run_sid_reverse.py <日志> --game fr_nx`已能回放符合协议的练级日志，报告显示每组等级及 EV 和确认击倒总数。它目前不是练级脚本启动器；也没有将旧包计数日志自动转换为可信记录的功能。

## 4. 接下来如何接入自动操作

### A. 先做独立、有限的采集测试

1. 选择日/美 ROM、经验接收方式、待测槽位、初始等级、来源、六项已知 EV、是否曾感染病毒和携带道具。
2. 在既定练级地点游戏内启动，先读取初始能力；所有身份与页面检测均使用该 ROM 对应标签。当前糖果 SID 模板的英文识图路径不能直接当成日版路径。
3. 只从参考包复用必要的遇敌和操作节拍。敌方物种使用 17 个支持目标的唯一最高分分类；未知或不确定敌人不进行击倒记账。
4. 明确待测宝可梦参加战斗，或仍携带学习装置且未濒死；看到可靠的击倒/经验结算后只提交一次 DEFEAT。
5. 消息结束与游戏内场景确认后，若待测宝可梦升级，读取实际等级、性格、性别、六项能力，关联当前 EV 快照；不能靠连续 A 次数猜等级。
6. 默认取消进化、不替换旧技能。低血量、缺 PP、濒死、消息超时或识别无法确认，停下保留现场；第一版不盲走医院和自动存档。
7. 初版限制战斗数、升级数、每阶段等待；没有无限 FOR。先做“只观察/不按键”和“单场战斗”测试，再跑有限多场。

学习装置还需单独验证经验文字属于谁、多只宝可梦经验消息、濒死资格和队伍位置。此时不能把第一个经验标签命中当作待测宝可梦已经获得 EV。

### B. 标签独立存放，运行器仍用 1.6.4a

- 日/美训练标签以独立命名空间存放在生成测试工程中，保存参考 ZIP、原标签名及 SHA-256 清单；同名但不同像素的两个语言标签不得相互覆盖。
- 不把旧包全部 ImgLabel 覆盖到 1155 项共同母本，不放宽正式完整资产数量检查来迁就旧包。
- 新工程若增加专用标签，应建立自己的明确清单和数量/方法审计；只准许已登记的附加标签，母本部分继续验证。
- 移植后的函数逐一通过锁定 1.6.4a `format`和真实绑定编译。1.61/1.63 声称可用不等于 1.6.4a 自动兼容。

### C. 正式页面接入

- SID 页增加“采集方式：神奇糖果 / 战斗练级”，默认保持糖果；选择练级才显示相关设置、已知风险和独立准备确认。
- 练级 worker 不运行糖果模板的关闭游戏/重启/三次整轮重试，不自动存档；无法确认时保留现场供用户核对。
- 日志逐行落盘并刷新每只宝可梦当前等级、累计 EV、确认击倒数、IV 区间、PID/PSV 候选；停止不会清空记录。
- 停止后要说明“工具日志中的进度”和“实际游戏是否保存”是两回事。未保存而重启后不能续用上次 EV 账本；恢复需重新核对真实等级与 EV。
- PID 已唯一时只在观测完成、无待发按键的安全点停止，再处理下一只；正式多只队伍轮转规则需按用户选择的接收方式实现，不能用原糖果逐槽位冷启动替代。

## 5. 验收矩阵

自动化：386 物种产出、1/2/3 点和倍率、255/510 截断顺序、独立队伍账本、重复消息/缺记录/顺序错误、初始观测、升级重算、多等级跳变、能力不可能、相同 PID 恢复、旧糖果日志及 SID 查找回归。

实机：日版/美版分别验证自己战斗与学习装置；正常击倒、逃跑、非目标闪光、未知敌人、缺 PP、低血量/濒死、连续升级、学习招式、进化取消、停止后不重启、不保存，及 UI/兼容运行器一致性。

**当前尚未执行实机矩阵，也未生成可以直接自动练级的 ECS。** 完成 Python 数据链只是第一阶段；下一步先交付单场/有限练级测试脚本供用户验收，再开放正式模式。

本轮已验证：新增24项测试、SID/IV相关定向68项及全量849项均通过；Python编译、`git diff --check`通过。两个真实 ZIP 的只读审计均发现18处选择阶段计数（17种支持物种加其他），17个引用标签没有缺项。原包代码不改。
