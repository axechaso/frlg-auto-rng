# PySide6 0.9 正式界面

正常启动时，主窗口会显示一次开源致谢与赞助公告；其中项目和开发者名称可点击，两张赞助图保持原比例展示。勾选“下次启动不再显示”并进入工具后，偏好单独保存在用户目录的 `startup_notice.json`；自动截图模式始终跳过公告。

2026-09-07：PySide6 已成为源码和 `0.9` 绿色版的正式入口。界面沿用已经确认的双栏布局、顶部快捷开关、紧凑存档与设备摘要；业务调用放在 `pyside_app/` 并复用已有搜索、生成、运行和持久化服务，不修改乱数算法或源 ECS。旧 Tk 仅保留在源码仓库作历史参考，不进入 `0.9` 安装包。

## 启动与操作

在仓库根目录双击 `启动-PySide6功能版.bat`，或运行：

```powershell
.\.venv\Scripts\python.exe run_pyside6_gui.py
```

首次需要安装 `requirements-auto.txt`；其中已经包含正式界面所需的 PySide6。`requirements-pyside-preview.txt` 只用于独立视觉预览。发布 EXE 直接启动本界面，目标电脑不需要另装 Python、PySide6 或 Tcl/Tk。

主窗口采用与侧栏相连的深蓝标题栏，设置、存档、方案、手柄和监视窗口使用浅色标题栏与细描边，去掉系统灰底和设置滚动区的方框。标题栏保留火稚鸡图标、拖动、最小化 / 最大化 / 还原 / 关闭；边缘缩放交给 Qt 的系统窗口接口。应用内弹窗保留原有输入与确认 / 取消语义；系统文件选择器和标准消息框继续使用系统外观。

1. 点击右上角存档信息，选择已有存档，或手动填写版本、语言、TID / SID；在主页面选择主机。
2. 在“共通设置”核对 2.0 脚本包和 `ezcon.exe`，在主界面顶部点击“重新检测”并选择串口、采集卡。
3. 选择野生 / 静态、遭遇方式、地点和宝可梦，填写 IV、闪光等筛选及消耗帧范围。静态分类可选择“游走”以及雷公、炎帝、水君；其 IV 按火红/叶绿截断规则搜索。指定模式需要明确选择 Seed 模式。
4. 点击“搜索并生成方案”。方案卡显示真实结果；详情中列出工程路径、路线要求、警告及预检错误。
5. 预检通过且设备就绪后，可点击“开始运行”。程序重新检查设备与生成文件；确认实际游戏设置和位置后启动。运行日志自动打开，“停止 EasyCon”始终直接可见。

更改条件、脚本路径或设备会使旧方案失效。搜索期间可以修改条件，但旧结果不会被接纳；运行期间锁定相关输入。关闭运行窗口会请求停止并等待本次进程结束。

“御三家连续乱数”的 Sound、Button Mode、Seed Button 仅在开启高级模式且勾选连续流程时可修改。“游戏设置与固定延迟”中的 Sound、Button Mode、Seed Button、取名进入键也仅在高级模式下可修改；关闭高级模式灰显并保留当前选择。御三家种类、ADV 范围和手动编辑固定延迟的启用规则保持原样。

TID 的 F2 / F1 候选阈值、去噪命中数、去噪窗口，以及各页可填写的识图阈值（SID、TID），均需开启高级模式才能编辑。关闭高级模式灰显并保留当前数值，生成仍采用所保存的值；字段悬浮说明同步标明编辑条件。

TID 的任意号码接续、去噪确认、额外目标与自动转乱数，其启用条件和互斥原因仅显示在控件悬浮说明中，灰显时也可查看；不新增常驻提示或问号。灰显的勾选保留原值，不代表当前生效。

各页复选框统一使用圆角方框：可操作且已勾选时为蓝底白勾；锁定时使用加深的灰底、灰色边框与深灰勾，文字也保持可读。鼠标悬停和键盘焦点有颜色反馈，启用与勾选规则不变。

SID 队伍与孵蛋页的宝可梦名称联想浮窗使用与普通下拉框相同的白底圆角、字体、行距、淡蓝选中项和细滚动条，最多显示八行。保留原有包含匹配、方向键 / 回车选取、Esc 取消和鼠标选择。

“重新检测、虚拟手柄、监视窗口”和串口 / 采集卡选择位于顶部高级模式附近，普通模式也可使用；窄窗口自动换行，运行准备卡只保留状态。顶部“虚拟手柄”只打开 JoyCon 浮窗，并自动连接当前所选串口，不显示大手柄窗口；重复点击复用已有连接。关闭浮窗会释放按键和串口，切换串口也会释放旧连接；未选串口或连接失败在主窗口状态区说明。

“共通设置 → 手柄键位”按实体手柄位置排列，包含双摇杆四向、摇杆按下、十字键四向 / 四个斜向、ABXY、肩键与系统键。点击对应位置后按键，Esc 清空。保存前检查重复键和 Windows 按键支持，取消或保存失败保留原映射。初次读入旧 18 键配置时保留已有键位，新摇杆方向优先使用图示键位，冲突时分配空闲 F 键；四个斜向默认未分配。“恢复图示键位”采用用户截图中的配置，不是上游伊机控的默认配置。

手柄浮窗沿用伊机控原版 100×100 JoyCon 图层、按键轮廓与绿色反馈，双摇杆随当前手动输入移动，中间四灯显示脚本运行状态。左键启用 / 暂停键盘，暂停时半透明并释放所有输入；中键或 Esc 关闭浮窗并停止键盘控制；右键拖动，右键单击回到主屏默认位置。操作说明放在浮窗悬浮提示内。

Windows 键盘输入通过系统虚拟键接收，绕开输入法组合文本与子控件焦点吞键。浮窗开启且串口已连接时可在监视窗口或其他窗口控制，仅拦截已映射按键。暂停、编辑键位、自动运行、断开及关闭时停止相应输入；关闭浮窗移除监听，未映射的按键仍交给当前应用。浮窗重开会重新启用，已有自定义键位不会被默认图示覆盖。

监视窗口沿用正式工具的 Switch 16:9 显示规则，独立采集时请求 1280×720；采集卡返回 640×480 等非宽屏缓冲时，在显示层恢复 16:9，不裁切画面或改写原帧。滚轮及工具栏的 − / + 按画面大小缩放，支持 320×180 至 1280×720，并受当前屏幕可用范围限制。双击切换仅画面模式，标题栏、工具栏、边框与外边距全部隐藏；仍可滚轮缩放、拖动画面移动窗口和拖动边缘缩放。再次双击或 Esc 恢复窗口。模式切换与缩放不重连采集设备；运行中仍读取原运行器的共享预览。

数字输入为空或不是整数时，错误提示标明具体字段；SID 等级还标明队伍位置。生成计划和刷新进度使用同一校验。运行日志遇到识图区域断言时，会保留标签名并优先提示检查采集卡占用、重连和画面，画面正常后再检查标签范围。此断言本身不能证明根因一定是占用或分辨率不匹配；其他识图低分、取消及未知错误不归为此类。运行结束后再次显示问题说明；原始错误和堆栈仍保留，原始日志文件不改写。日志按分段 UTF-8 接收时也保留完整行尾。

TID 的“刷新进度”位于底部生成计划按钮左侧，仅在 TID 页显示；原续跑分区保留开关和进度说明。按钮读取同参数的检查点并回填 OP / F1 / F2“穷举起点”：将保存的偏移换算为总帧起点；已自动转入局部乱数时，回填对应的穷举返回位置。进度说明同时显示当前目标、中心、各轴实际负向 / 正向范围、当前壳层与累计次数。半径等其他输入保持原值；没有有效检查点、已命中完成或手动乱数时不回填。运行或后台任务期间只更新说明，启动、自动保存和运行中轮询也不会自动改动起点。

勾选“继续同参数的上次搜索进度”后，回填仅改变起点显示，重新生成并启动仍恢复原搜索位置、层级、范围及局部搜索历史。手动修改任一起点、半径、身份、游戏设置等搜索条件，或取消续跑后，显示的起点作为新的请求参数。Qt 重开窗口保留回填显示；共享 `tid_settings.json` 的标准 `values` 仍保存原起点，另以 `qt_progress_refill` 记录显示与原参数的对应关系，确保正式 Tk 与原检查点兼容。检查点文件本身不改写。

## 数据与代码边界

- 现有存档、实测数据库、预校准和标签覆盖位于 `%LOCALAPPDATA%\FRLG-Auto-RNG`。
- Qt 自己的 2.0 / SID / TID 脚本包及 exe 路径保存在同目录 `pyside6_settings.json`；TID 草稿使用正式 `tid_settings.json`。孵蛋配置可导出；其余本次筛选条件保留在窗口内。
- Qt 键位写入用户目录 `pyside6_controller_keymap.json`；初次使用可读取此前 `manual_controller_keymap.json` 的 18 键配置，保存不覆盖旧文件。
- 每次生成使用独立 `runtime/pyside6/<流程>-<id>/`，保存搜索结果、工程清单、ECS 副本与独立运行日志，不覆盖上一次结果。脚本测试按用户所选路径原地执行。
- `--data-dir <目录>` 可隔离测试用资料与生成目录。`--screenshot <PNG>` 实际显示窗口后截图，自动跳过设备检测，不执行脚本。
- `pyside_preview.py` / `启动-PySide6界面预览.bat` 仍是纯内存预览，不导入业务模块；本文件描述的接入只属于 `run_pyside6_gui.py`。
