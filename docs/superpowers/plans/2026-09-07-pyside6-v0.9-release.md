# PySide6 0.9 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `FRLG Auto RNG 0.9` with PySide6 as the packaged UI, a working Qt self-update flow, and verified direct upgrade from the public `0.2.2` release.

**Architecture:** Keep `app_updater.py` and `update_installer.py` as the UI-independent release and directory-swap boundary. Route `package_entry.py` to `run_pyside6_gui.py`, add a focused Qt update controller, and update the existing PyInstaller/release scripts to build and publish one onedir PySide6 package while preserving the schema-1 update contract.

**Tech Stack:** Python 3.12, PySide6 6.11.2, PyInstaller 6.15.0, truststore 0.10.4, PowerShell, GitHub CLI, EasyCon 1.6.4-a+9c86137.

**Spec:** `docs/superpowers/specs/2026-09-07-pyside6-v0.9-release-design.md`

## Global Constraints

- Display version is exactly `0.9`, version code is exactly `2026090701`, and the Git tag is exactly `v0.9`.
- The package keeps `FRLG-Auto-RNG.exe`, `FRLG-Auto-RNG-Updater.exe`, `_internal`, and update schema `1`.
- Normal packaged startup uses PySide6 only; old Tk source remains in the repository as historical reference.
- `%LOCALAPPDATA%\FRLG-Auto-RNG` is external to the install swap and must remain byte-for-byte unchanged by update tests.
- Formal EasyCon support remains `1.6.4-a+9c86137`; do not claim 1.70 or 1.6.3 support.
- Do not alter ECS Seed/frame algorithms, game routes, or current runtime workflow order.
- Do not create a PR. Push `main`, require successful GitHub Actions for the release commit, then publish `v0.9`.
- Preserve unrelated untracked `tools/EasyCon164aCommonRegionCheck/bin/` and `obj/` directories and never stage them.

Create `pyside_app/app_update.py` with a controller shaped as:

```python
class AppUpdateController(QObject):
    def __init__(self, window, *, frozen: bool | None = None):
        super().__init__(window)
        self.w = window
        self.frozen = is_frozen_build() if frozen is None else frozen
        self.candidate = None
        self.status = self._find_status_label()
        self.button = window.actions["检查程序更新"]
        self.auto_timer = QTimer(self)
        self.auto_timer.setSingleShot(True)
        self.auto_timer.timeout.connect(lambda: self.check(force=False))
        if self.frozen:
            self.auto_timer.start(1800)

    def check(self, *, force: bool = True):
        if not self.frozen:
            self.status.setText("源码模式不使用程序自更新；请通过 Git 获取更新。")
            QMessageBox.information(self.w, "程序更新", self.status.text())
            return
        self.w.launch_job(
            lambda _cancel, _status: check_for_update(
                current_version_code=APP_VERSION_CODE,
                cache_dir=self.w.paths.user / "updates",
                force=force,
            ),
            lambda result: self._checked(result, force),
            "正在检查程序更新……",
            allow_while_running=True,
        )
```

Use `prepare_update(candidate, install_dir=Path(sys.executable).resolve().parent, updates_root=self.w.paths.user / "updates", cancelled=cancel)` for preparation. After preparation, call `write_install_request`, copy the installed updater to the request directory, launch it with `subprocess.Popen`, set a dedicated `closing_for_update` flag, and call `window.close()` only after launch succeeds. Do not duplicate manifest or ZIP validation.
