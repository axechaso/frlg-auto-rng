# PySide6 0.9 正式发布设计

日期：2026-09-07

## 目标

将已经接入完整业务流程的 PySide6 界面作为 `FRLG Auto RNG 0.9` 的唯一正式打包入口，并保持现有整包更新协议不变，使公开的 `0.2.2` 绿色版能够通过内置更新器直接升级到 `0.9`。发布物必须包含完整绿色版、独立更新器、更新清单和 SHA-256 校验文件；使用者不需要安装 Python。

版本与发布标识固定为：

- 显示版本：`0.9`
- 版本代码：`2026090701`
- Git 标签：`v0.9`
- 发布标题：`FRLG Auto RNG 0.9 PySide6版`
- 目录与 ZIP：`FRLG-Auto-RNG-0.9-windows-x64`

## 当前状态与兼容性结论

现有更新器不是对 Tk 文件做增量修补，而是在主程序退出后交换整个安装目录。它只依赖稳定的发行合同：

- 主程序仍名为 `FRLG-Auto-RNG.exe`；
- 独立更新器仍名为 `FRLG-Auto-RNG-Updater.exe`；
- ZIP 根目录直接包含主程序、更新器和 `_internal`；
- 新主程序继续支持 `--version-json`、`--version-json-file`、`--update-health-file` 和 `--update-health-token`；
- manifest schema 保持为 `1`，新 `version_code` 大于 `0.2.2` 的 `2026090302`。

因此界面技术从 Tk 切换到 PySide6 不要求修改安装交换协议。只要 `0.9` 继续满足以上合同，`0.2.2` 可以直接发现、下载、校验并安装 `0.9`。`0.2.1` 及更早版本若本机 HTTPS 证书链能够正常访问 GitHub，也可遵循同一协议直升；若旧版受已知证书链问题影响，需先手工安装 `0.2.2` 或 `0.9`，不能通过关闭 TLS 校验规避。

## 正式入口

`package_entry.py` 继续作为 PyInstaller 和更新器探针入口，并保留全部无界面参数及后台 worker 分派。普通启动和更新健康检查完成后的界面启动改为调用 `run_pyside6_gui.main()`，不再调用 `run_auto_rng_gui`。

`run_auto_rng_gui.py` 保留在源码仓库作为历史实现和迁移参考，但不进入 `0.9` 的正常启动路径，也不作为新发布功能是否完成的判断依据。

`run_pyside6_gui.main()` 必须接受来自 `package_entry.py` 的参数列表，避免直接读取包含内部更新参数的原始 `sys.argv`。更新健康检查写入成功后应以普通 PySide6 启动继续运行，并显示主窗口；启动公告仍遵守用户的“不再提示”设置。内部健康检查本身不能被公告阻塞，更新器应能在窗口继续运行时及时确认新版本已经启动。

## PySide6 程序更新入口

PySide6 共通设置中的“检查程序更新”从说明性按钮改为正式功能，直接复用经过验证的 `app_updater.py` 后端，不复制 Tk 控制器代码。新增 Qt 专用控制器，职责为：

1. 启动后仅在冻结绿色版中按现有 24 小时缓存策略后台检查最新正式 Release；源码模式不自动联网。
2. 手动点击始终允许强制检查；源码模式明确提示程序更新通过 Git 获取，不尝试替换源码目录。
3. 展示当前版本、新版本、发布日期、下载大小和 manifest 中的更新说明。
4. 用户确认后在后台下载并准备更新；保留取消、进度、哈希、大小、ZIP 路径和内嵌版本校验。
5. EasyCon 或其他工作进程运行时允许检查，但禁止安装；安装前再次确认程序空闲。
6. 准备成功后复制独立更新器到用户更新目录，写入安装请求，启动更新器并关闭主程序。
7. 网络、证书、清单、空间、下载、校验或启动失败均以 Qt 错误提示和日志呈现，不退出当前可用版本。

Qt 控制器只负责界面线程调度、对话框和主窗口生命周期；Release 解析、下载、解压、安全检查、安装请求和目录交换继续由现有共享模块负责。

## 用户数据与升级保留

更新仍只替换绿色版安装目录。以下用户目录内容不得进入交换、删除或重置范围：

- 存档与常用设置；
- TID/SID 参数、实测表和续跑进度；
- 日志与运行时生成工程；
- 当前 Seed 表和上一版 Seed 表；
- 采集设备标签覆盖；
- PySide6 手柄键位与窗口配置；
- `startup_notice.json` 中的“不再提示”选择；
- 孵蛋亲本配置与全部配置。

这些数据继续位于 `%LOCALAPPDATA%\FRLG-Auto-RNG`。发行 ZIP 不包含开发机的用户数据、运行日志、临时工程或绝对路径。

## Windows 打包

`tools/build_windows_release.ps1` 改为构建 PySide6 正式入口：

- 安装并锁定发布所需的 PyInstaller、PySide6、truststore 和现有运行依赖；
- 收集 PySide6 Qt plugins、图像格式插件及项目运行所需的动态模块；
- 保留 EasyCon `1.6.4-a+9c86137`、兼容 runner、OCR、1150 个标签、Seed 表、图标和赞助图片；
- 不再把 Tcl/Tk 和 tkinterdnd2 当作正式界面运行时硬依赖；
- 继续使用 `onedir`，随后压缩为标准 ZIP；
- 继续单独构建 `FRLG-Auto-RNG-Updater.exe`；
- 构建后运行冻结主程序版本探针和 PySide6 无设备启动冒烟；
- 检查 ZIP 内不存在源码虚拟环境、Git 凭据、用户配置、日志、构建机用户名或意外绝对路径。

若共享 worker 仍通过动态导入调用，PyInstaller 必须显式收集这些模块。发布包必须能在未安装 Python 的 Windows 环境中启动主界面、执行版本探针和运行独立更新器。

## 直升验证

在公开发布前使用本地隔离目录验证旧版到新版的完整边界：

1. 下载或解压公开 `v0.2.2` 的正式绿色包作为旧安装目录。
2. 使用本次生成的 `0.9` ZIP、manifest 和 SHA-256 走与客户端相同的校验与暂存流程。
3. 由独立更新器交换旧目录与 `0.9` 目录。
4. 确认新 `FRLG-Auto-RNG.exe` 写出版本代码 `2026090701` 的健康标记并启动 PySide6。
5. 在测试用户目录预放代表性配置、进度、Seed 表、设备标签覆盖和公告隐藏设置，确认更新后字节不变。
6. 模拟新程序健康检查失败，确认自动恢复 `0.2.2` 安装目录且用户数据不变。

不能在公开 `v0.9` 尚不存在时声称真实 GitHub 在线发现已通过；发布前使用本地候选和安装器完成交换验证，发布后再以公开 Releases API 做一次不登录的最终发现与清单核对。

## 自动化测试与发布门槛

新增或更新测试必须覆盖：

- 版本常量、文件名和 `v0.9` manifest；
- `package_entry.py` 普通启动进入 PySide6，worker 与更新探针保持兼容；
- 更新健康启动不会被公告阻塞；
- Qt 自动检查、手动检查、当前已最新、发现新版、用户取消、程序忙碌和错误提示；
- 下载准备完成后启动独立更新器并安全关闭主窗口；
- 构建脚本收集 PySide6、移除 Tk 正式依赖并执行冻结冒烟；
- `0.2.2 → 0.9` 成功交换、用户数据保留和失败回滚；
- 完整 Python 测试、相关 EasyCon `Tools/check_*.py` 以及真实 `ezcon.exe format` 检查保持通过。

发布顺序固定为：

1. 完成实现和本地验证；
2. 提交并推送 `main`；
3. 等待当前提交的 GitHub Actions 成功；
4. 构建唯一的 `0.9` 发布目录和三个发布资产；
5. 创建草稿 Release，上传 ZIP、`update-manifest.json` 和 `.sha256`；
6. 回读资产名称、大小和清单，确认无误后设为正式且 latest；
7. 通过公开 API 下载并核对 manifest、版本、包名、大小和 SHA-256；
8. 将最终发布证据写入交接文档并推送。

任何校验失败都不得留下资产不完整的正式 Release；草稿保留供检查。不得创建 PR，也不得覆盖已有同名 tag 或 Release。

## 0.9 更新说明

Release 正文采用面向使用者的中文说明，至少包含：

### 主要更新

- 正式界面全面迁移到 PySide6，统一侧栏、卡片、日志页、设置窗口和手柄/监视浮窗。
- SID 查找、TID 乱数与实测表、野生/静态、孵蛋、高级脚本测试、Seed 更新及设备标签管理均接入新界面。
- TID/SID 到御三家连续流程、固定延迟自动回填、续跑进度、SID ADV 同奇偶优先和成功修正回写。
- 2.0 脚本、御三家校准可信门控、严格跨轮候选筛选、帧与 Seed 双命中保持。
- 新增程序启动公告、项目致谢与可选“不再提示”。

### 升级方式

- `0.2.2` 用户可在旧版中点击“检查程序更新”直接升级到 `0.9`。
- 更新只替换程序目录，不覆盖 `%LOCALAPPDATA%\FRLG-Auto-RNG` 中的配置、日志、进度、Seed 表和设备标签。
- 绿色版不需要安装 Python；解压后也可直接运行 `FRLG-Auto-RNG.exe`。

### 使用边界

- 正式 EasyCon 目标仍为 `1.6.4-a+9c86137`，不把 1.70 或 1.6.3 声明为正式支持。
- 自动化与格式检查不能代替 Switch 实机命中验证；首次长跑前应检查游戏位置、存档、单片机、采集卡和标签匹配。

## 非目标

- 不删除旧 Tk 源码，也不继续为其同步新功能。
- 不改变 ECS Seed/帧轴算法、路线或 EasyCon 正式版本合同。
- 不改成单文件主程序。
- 不支持静默强制更新、预发布自动更新或跳过 TLS/哈希校验。
- 不把应用更新器改为 GitHub Actions 自动发布；发布仍由经过预检的本机脚本执行。
