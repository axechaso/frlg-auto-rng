# 日版 TID 专用 OCR 采集、训练与接入设计

日期：2026-08-31
目标运行时：EasyCon `1.6.4-a+9c86137`

## 1. 背景与目标

现有日版训练家卡片的 TID 识别依赖五个数字位置的图标标签。实际运行中，屏幕亮度、采集状态和画面细微变化会造成连续多轮标签识别失败；恢复正常亮度后又可能重新识别成功。现有 50 个日版标签文件只有 36 份唯一图像，且都是单个数字的小尺寸裁剪，不能覆盖完整五位 TID 的字距、亮度变化和采集噪声。

本设计增加一套只用于日版训练家卡片五位 TID 的专用 OCR 数据链路：从真实实机画面采集、人工确认真值、训练独立模型、离线验证，再以“影子模式”接入脚本。模型通过验证后，也只能与现有图标标签互相校验，不能单独决定 SID 计算或后续桥接流程。

第一阶段先交付可试用的截图采集器和数据集校验器，不立即改变现有 ECS 运行行为。

## 2. 范围

### 2.1 本次包含

- 从兼容运行器的本机 MJPEG 预览流读取最新画面，不重复打开采集设备。
- 裁剪日版训练家卡片 TID 区域，并保存单行五位数字训练样本。
- 由用户确认或输入画面上的真实五位 TID，生成同名 `.gt.txt` 真值文件。
- 保存采集会话、画面状态、原图哈希、真值和裁剪参数等清单元数据。
- 校验真值、去重、检测真值冲突，并按训练家卡片/会话分组划分训练集与验证集。
- 使用官方 `tesstrain` 流程，从 `tessdata_best/eng` 的浮点模型微调独立模型 `frlg_tid_jp.traineddata`。
- 用完整五位 TID 的严格准确率评估模型，并记录逐位混淆情况。
- 后续在日版流程中先影子运行，再启用 OCR 与图标标签的交叉校验。

### 2.2 本次不包含

- 不修改英文 OCR 模型或英文版参数。
- 不覆盖 `FRLG_EN_ALL.traineddata` 或 `frlg_battle.traineddata`。
- 不使用云端视觉模型，也不把 OCR 自身输出直接作为训练真值。
- 不调整 OP、Seed、帧轴、路线或按键时序。
- 不在缺乏真实独立验证数据时宣称模型已提高命中率。
- 不让采集工具发送任何手柄输入。

## 3. 核心安全约束

OCR 的“三次读取、两次相同”只能减少随机波动，不能排除稳定地读错同一个数字。因此正式接入必须同时满足以下规则：

1. 五个图标标签都识别成功时，OCR 结果必须与五位标签完全一致。
2. 恰好一个位置的图标标签缺失时，OCR 只允许补这个位置；其余四位必须与标签一致。
3. 缺失两个及以上位置、OCR 与已有标签冲突、OCR 不是恰好五位数字，均判定失败并重试。
4. 失败状态不得用于 SID 计算，也不得进入命中后的桥接流程。
5. 模型缺失、哈希不符或 OCR 功能关闭时，脚本继续使用原图标标签流程。

第一轮 ECS 接入只记录 OCR 结果和交叉校验结果，不影响控制流，称为“影子模式”。

## 4. 数据采集设计

### 4.1 数据来源

兼容运行器已经支持 `--preview-port <port>`，并在本机回环地址提供最新帧 MJPEG。采集器连接 `http://127.0.0.1:<port>/mjpeg`，取得完整 1920×1080 画面后裁剪 TID 区域。初始候选区域为：

```text
x=1280, y=105, width=360, height=125
```

该区域只是根据现有日版数字标签外接范围得到的起点。采集器必须支持命令行覆盖，并在首张样本前保存完整画面和带框预览，以便实机确认后再固定参数。

### 4.2 第一阶段采集器

新增 `tools/tid_ocr_jp_capture.py`，职责如下：

- 读取回环 MJPEG，不访问外网。
- 在控制台显示当前裁剪参数、预览端口和采集会话编号。
- 从用户输入取得恰好五位数字真值；保留前导零。
- 按一次确认只保存一个样本，避免连续帧无意义堆积。
- 同时保存裁剪图、同名 `.gt.txt`、清单记录；可选保存该会话首张完整画面。
- 记录正常亮度/变暗状态，由用户明确选择，不通过 OCR 猜测。
- 退出或连接失败时不修改 ECS、模型或采集设备状态。

建议命令形式：

```powershell
python tools/tid_ocr_jp_capture.py --preview-port 19080 --brightness normal
python tools/tid_ocr_jp_capture.py --preview-port 19080 --brightness dim
```

### 4.3 数据目录

真实截图含用户实机画面，且数据量会持续增长，因此默认保存在 D 盘工具工作区的 Git 忽略目录 `D:\Codex\火叶乱数\frlg-auto-rng\runtime\tid_ocr_jp_dataset\`，不写入 C 盘下载包：

```text
runtime/tid_ocr_jp_dataset/
  raw/
    <session-id>/
      <sample-id>.png
      <sample-id>.gt.txt
      full-frame-reference.png
  manifest.jsonl
  prepared/
    train/
    eval/
    split-manifest.json
```

训练和校验代码进入 Git；真实截图默认不提交。后续训练缓存、检查点和候选模型也放在 D 盘工作区的 `runtime/tid_ocr_jp_training/`，不复制到 C 盘；只有模型通过验证并进入明确的部署阶段后，才按部署计划复制最终产物。若以后需要发布公共训练集，应另行审查隐私、授权和体积。

### 4.4 清单字段

每个样本在 `manifest.jsonl` 中保存：

- `sample_id`
- `session_id`
- `card_id`：同一张训练家卡片的稳定分组标识
- `tid_text`：长度恰好为 5 的字符串
- `brightness`：`normal` 或 `dim`
- `roi`：`x/y/width/height`
- `source_width/source_height`
- `image_sha256`
- `captured_at`
- `preview_port`
- `ground_truth_source`：第一阶段固定为 `manual`

`card_id` 不使用 TID 本身自动推导，以免相同 TID 的不同设备或不同会话被误当成同一张卡；由采集会话显式指定或自动生成后由用户复用。

## 5. 数据校验与划分

新增 `tools/tid_ocr_jp_dataset.py`，执行以下硬校验：

- `.png` 与 `.gt.txt` 必须成对出现。
- 真值必须匹配 `^[0-9]{5}$`，包括前导零。
- 裁剪尺寸必须与清单一致且位于原画面范围内。
- 同一图像哈希对应不同真值时立即报错，不能自动选择。
- 同一图像哈希和相同真值只保留一个训练样本，并在报告中列出重复来源。
- 训练/验证划分按 `card_id` 分组；同一训练家卡片的近似帧不得跨集合。
- 默认 80% 训练、20% 验证，并尽量让正常/变暗样本都出现在两组。

现有 36 份唯一日版数字图标可用于生成训练增强样本，但不得进入验证集，也不得替代真实完整五位 TID 样本。

首轮训练前至少采集约 100 个不同 `card_id`；若当前条件只能得到较少卡片，第一阶段仍可验证采集器，但不得把其训练结果作为正式模型发布。后续应扩充到数百张卡片，并覆盖正常亮度、约五分钟后的变暗状态以及真实采集噪声。

## 6. 训练设计

### 6.1 工具链

本机当前没有 `tesseract`、`lstmtraining`、`combine_tessdata`、`text2image`、`make`、Docker 或可用 WSL，因此训练环境是独立里程碑。安装或下载训练依赖前需要用户明确允许。

训练采用 Tesseract 官方 `tesstrain` 工作流：每张单行图片配同名 `.gt.txt`，以 `tessdata_best/eng` 浮点模型为 `START_MODEL` 进行微调。不能从现有 `FRLG_EN_ALL.traineddata` 推定可继续训练，也不从少量样本完全从零训练。

训练字符范围仅为 ASCII 数字 `0-9`，模型名称固定为：

```text
frlg_tid_jp
```

### 6.2 可复现输入

训练命令必须固定并记录：

- `tesstrain` 和 Tesseract 版本或 Git 提交。
- 起始模型来源与 SHA256。
- 数据集 `split-manifest.json` 的 SHA256。
- 最大迭代数、学习率和随机种子。
- 最终 `.traineddata` 的 SHA256。

原始采集图先保留；缩放、对比度、亮度和轻微模糊等增强在准备阶段生成，并由固定随机种子复现。验证集不做训练增强。

## 7. 评估与验收

单字符准确率不足以保证五位 TID 安全。评估报告必须包含：

- 验证集样本数和独立 `card_id` 数。
- 五位字符串完全一致率。
- 错误样本清单：真值、预测、亮度、会话、图像路径。
- 每个数字的混淆统计。
- 正常亮度与变暗状态分别的完全一致率。
- 每张图片是否得到恰好五位数字。

进入影子模式前，当前冻结验证集必须达到零个五位错误；如果验证集过小，只能说明“尚未发现错误”，不能据此证明生产可靠性。

影子模式至少记录以下内容：图标识别的五个位置、OCR 三次原始结果、投票结果、交叉校验结论和亮度状态。只在获得足量不同 TID/会话且没有错误接受后，才进入混合校验模式。即使进入混合模式，也继续遵守第 3 节的标签约束，不提供 OCR-only 开关。

## 8. 模型部署与 ECS 接入

模型部署到 EasyCon 的 `publish/Tessdata/frlg_tid_jp.traineddata`，与现有模型并存。资产准备和启动前检查需要增加该模型的独立文件名、长度和 SHA256，不得放宽现有两个模型的校验。

ECS 调用形式为：

```text
OCR(x, y, width, height, "frlg_tid_jp")
```

接入时遵守 EasyCon 1.6.4-a 约束：共享状态在主脚本全局区声明，库函数所需状态通过参数传入；两份主脚本的公共逻辑同步修改。OCR 开关仅对日版生效，英文版仍使用现有模型和参数。

影子模式仅 `PRINT` 诊断结果；混合校验通过后才向现有 TID 识别函数返回候选值。任何失败均回到原来的重试路径。

## 9. 错误处理

- 预览流未启动、断开或帧无法解码：报告原因，不写样本。
- 画面分辨率或 ROI 不符合预期：拒绝采集，并输出实际尺寸。
- 用户输入不是五位数字：拒绝保存，允许重新输入。
- 同图冲突真值：数据集校验失败，必须人工处理。
- 模型训练失败或验证不达标：不部署、不接入 ECS。
- 模型文件缺失或哈希不符：启动前检查失败；已发布脚本保持标签识别路径。
- OCR 输出空、非数字、位数不为五或与标签冲突：判定本轮失败，不进行任何下游计算。

## 10. 测试策略

第一阶段为采集器和数据集校验器增加自动化测试：

- 从含分块边界的模拟 MJPEG 流提取完整 JPEG 帧。
- 预览连接失败、空帧和损坏 JPEG 的错误处理。
- ROI 边界、分辨率和裁剪尺寸检查。
- 五位真值及前导零的保存与读取。
- 图像去重和冲突真值检测。
- 按 `card_id` 分组切分，保证训练集和验证集无泄漏。
- 清单中相对路径、哈希和会话字段的一致性。

模型阶段增加离线评估测试和固定小型夹具。ECS 阶段仍须用真实 `1.6.4-a ezcon.exe format` 检查两份主脚本，并运行仓库全部 `Tools/check_*.py`。实机影子测试与离线测试分开记录，不能用模拟截图替代硬件验收。

## 11. 实施里程碑

1. 实现只读截图采集器、数据目录忽略规则、数据集校验器及测试。
2. 用日版训练家卡片采集正常与变暗状态的真实样本，人工确认真值。
3. 经用户允许后准备官方训练环境，生成候选 `frlg_tid_jp.traineddata`。
4. 运行分组验证和错误审计；未达标则只继续补充数据/调整训练，不部署。
5. 增加日版影子模式，记录 OCR 与标签对照，不影响现有流程。
6. 影子数据达标后启用受标签约束的混合校验，并执行 1.6.4-a 全量检查与实机验证。
