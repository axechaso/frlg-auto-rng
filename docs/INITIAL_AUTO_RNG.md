# 火红/叶绿全自动乱数首版

这条新流程不部署视觉语言模型。Python 只负责 Ten Lines 搜索、自动择优和生成 1.1.8 ECS 参数；真正运行时由本机 EasyCon 1.6.4a 的 `ezcon.exe` 控制单片机和采集卡，并使用 1.1.8 自带标签及本地 Tesseract 数据。EasyCon 1.7.0 当前不在支持范围内。

## 用户流程

1. 连接单片机和采集卡。
2. 可先在窗口顶部“管理存档”登记名称、游戏版本、TID、SID 和 Switch 机型。该设计对应 PokeFinder 的 Profile 管理，并增加本工具的 NX 机型；选择后自动同步四页相关字段。选择“未选择（手动输入）”则保持原有手动填写方式。
3. 如需先确认 SID，使用第一页“SID 查找”：填写主机、TID、队伍闪光数量及每槽宝可梦、初始等级、来源/地点/努力值，准备并启动逐只采集；PSV 唯一后报告会回显到主界面。
4. 在“野生 / 静态”选项卡填写游戏、TID/SID、目标宝可梦、遭遇地点、IV/性格/特性/觉醒力量等条件以及最大 Advance。六项 IV 各有独立的最低/最高输入和单项重置，并提供不限、6V、0A、0S、0A0S 预设；预设语义与 Ten Lines 一致，0A/0S 的其他项固定为 31。
5. 点击“搜索并生成方案”。
6. 程序从 IV 总和最高的一层开始搜索；有多个同总和结果时，选择可行初始 Seed 中 Advance 最小者。
7. 完整搜索后没有符合条件的结果时提示放宽条件；若达到首版工作量安全上限，会明确提示“搜索未完成”，不会误报无结果。
8. 碎岩、狩猎区或其他实验路线仍显示并保存计划，但不生成可启动脚本。
9. GUI 启动后会先静默枚举一次设备。串口与采集卡均从下拉框选择，采集卡项显示 EasyCon 序号和设备名；当前项仍在线时重检会保留，否则自动选择数字最小的可用项。
10. 预检通过后点击“开始运行”。进程成功启动后 GUI 自动切换到常驻的“运行日志”页并实时读取本次日志；原始 `ezcon.exe` 负责固定版本/哈希、设备、Tessdata 与 `format` 预检，实际执行使用同一 1.6.4-a commit 构建的 CLI 兼容 runner，使 ImgLabel 分数取整与伊机控 GUI 的 `Math.Ceiling` 行为一致。
11. 需要隔离排查 ECS、原始 1.6.4-a CLI 与工具兼容 runner 时，勾选公共设置中的“高级模式”，使用默认隐藏的“脚本测试（高级）”页；它不参与正式方案生成。

存档信息只保存工具参数，不会接触实际游戏存档。JSON 位于 `%LOCALAPPDATA%\FRLG-Auto-RNG\save_profiles.json`，源码版和打包版共用。火红/叶绿不使用实时时钟电池，因此不保存枯电池状态。

公共工具区的“检查/更新 Seed 表”不调用外部 `.py`。它下载 Ten Lines 官方火红/叶绿 NX 二进制表，由同一份数据生成 Python 搜索表和 EasyCon ECS 表，校验完整文件指纹，并让正式入口和孵蛋入口都通过真实 1.6.4-a `format` 后才原子切换。失败时继续保留旧表；绿色打包版用户不需要安装 Python。

运行入口：

```text
安装-自动乱数首版.bat
启动-自动乱数首版.bat
```

首次安装会同时校验 1150 个标签，以及正式入口、孵蛋测试入口、SID 采集入口和 31 个 `lib` 文件。正式/孵蛋入口与 `lib` 的固定语料仍为 33 项，SID 入口另外校验存在后一起导入到被 Git 忽略的 `local_assets/easycon118/`。安装器接受已经登记的历史指纹，复制完成后把 1.6.4-a OCR、HOME_BUFFER、孵蛋重试、冲浪和队伍导航修正写入本地正式/时间轴入口及共享库，再记录物化后的指纹。用户可能直接更新下载包脚本，因此未知语料指纹只打印警告并继续导入、生成和审计；缺少必需入口、库、标签或格式检查失败仍会终止。

后端固定为 `1.6.4-a+9c86137c7e63bff842175470895727a5fa9bab52`，默认读取 `Downloads\伊机控-EasyCon-v1.6.4alpha测试版-260518\publish\ezcon.exe`。安装器还会从 1.1.8 包复制并校验 `frlg_battle.traineddata` 与 `FRLG_EN_ALL.traineddata`；原始 1.6.4a 压缩包并不包含这两份火叶模型。1.1.8 原脚本也明确声明当前只确认适配 1.6.4a；未重新验收前不会自动接受 1.7.0 或其他构建。

也可以使用命令行，只生成而不启动：

```powershell

  --iv-max 29/31/27/29/29/30
```

只有显式增加 `--run` 才会启动硬件流程。

## TID 到御三家

当前已同步同一文件的 `2026-08-28-r2`。美日两版的新建存档检测仍位于OP按键释放后、下键及随后A键之前，在原500ms窗口内采样。r2原样同步最新二楼/一楼/镇上摇杆路线；球前覆盖存档改为 X 后等待1000ms，直接 `DOWN / WAIT 500` 两次、`A / WAIT 1500` 六次、`UP / WAIT 500 / A / WAIT 2500`，不加入保存成功识别。

穷举OP/F1/F2起点默认全为0，原脚本自动提升到可执行最小值；手动设置并保存的值不强制归零。TID输入和开关自动保存到用户目录 `tid_settings.json`，穷举状态按游戏/机型/参数/模板指纹存到 `tid_progress/`。默认续跑上次未完成搜索，恢复原偏移、搜索层级及OP运行修正，当前点重新进行去噪观察；不改变原搜索算法、固定帧基准或操作时序。命中后标为完成，不恢复御三家后续阶段的中途画面。

停止、关闭以及后台持续运行都由工作进程保存检查点；GUI关闭可选停止后关闭或保留后台。停止通知使用私有的每次运行独立文件，普通/孵蛋/TID/SID/高级测试均不再依赖跨控制台信号；5秒未退出时，仅清理本次进程树。不会按 `ezcon.exe` 或 `python.exe` 名称批量结束其他任务。更新前的旧进程需人工关闭一次，重启工具并重新生成后才使用新逻辑。

此前r3的机型差保留且只作用于实际OP等待：NS1为0、NS2为−750ms；OP目标帧和固定延迟回填仍使用各语言未扣机型差的基准。校准输出已自动还原机型差，工具不再次加减；如果旧NS2参数曾人工扣750ms，应重新做固定延迟检查，不能叠加旧补偿。NS1配置不自动改写。

检测失败后仍自动增加OP实际等待50ms并清空观察窗口重开，最多10次，不变更OP校准基准或F1/F2。共用美日HOME_BUFFER、固定延迟检查自动回填四项及实际OP修正均保留；HOME_BUFFER自适应开关不作用于新建存档检测。球前阶段沿用原路线，日志只确认存档按键执行完毕，保存结果仍需实机确认。

2026-08-28 用户确认的更新源是 1.1.8 目录中的 `NS火叶TID-SID到御三家球前存档-测试.ecs`，不是单独的英文 v2。其英日文同步按键、同语言 F1/F2 参考余数换算和新的球前覆盖存档顺序原样接入；生成器只填写当前语言用户区，保留全局声明和另一语言原文。ID 副本去除自动走位收尾，第二阶段直接提取同一文件的五个 `FLOW_` 函数，避免重复走球前路线；1.1.8 第三阶段不变。缓存已经同步，旧生成工程需要重启工具后重新生成。

生成目录 `plan.json` 记录实际模板名、指纹和 `starter_save_164a` 类型，界面也显示实际文件名。模板优先级为球前存档版、英文 v2、旧 1.3.7；无新版资产时仍兼容旧包。导入器默认从 1.1.8 下载目录同步球前存档文件，保留 TID 专用 328 标签与旧模板；换设备须复制此文件或整个 `local_assets/tid_rng137`。同步按键后的英文 OP 默认固定延迟为 30600ms，日文为 30650ms；已有用户值不自动猜测补偿，首次运行新版请做固定延迟检查并自动回填。HOME_BUFFER 自适应默认仍关闭，开启时同样使用同步按键。

TID 页保留目标 TID/SID 乱数和 TID 穷举两条连续流程。目标模式会提前用目标身份搜索御三家，并在精确 PID 不闪时按 SID ADV 修正范围重新建档。穷举默认仍需命中原五种启用的号码条件；新增“取得任意TID后继续”选项才会忽略目标TID/特殊号码。任意TID的去噪另有开关，默认开启；关闭后首次完整、合法的号码识别即可接续。两条穷举路径都输出实际 TID 与 SID ADV，Python 按 1.3.7 的 ADV 约定计算实际 SID，再从用户给定范围搜索最早闪光御三家、生成 1.1.8 `Starter` 阶段并执行 1.6.4-a 预检。完整性和0–65535合法性检查不关闭。

F3 随机模式已经移除。界面只提供“目标 SID（自动计算 ADV）”和“固定 F3 延迟（采用实际 SID）”；连续穷举自动使用后者。单独TID和连续御三家都可勾选“先检测固定延迟，完成后自动运行计划”：后台第0阶段测齐OP/F1/F2/F3与实际OP修正，GUI自动回填并关闭检测；后台用原请求快照和测量值在新目录生成、预检，再自动运行正式阶段。缺项、取消或异常不衔接；完整测量后的生成/预检失败会保留测量值并停止。用户在检测时修改界面则不覆盖新输入。四项输入默认不可手动编辑，需要时可开启“手动编辑固定延迟”。

SID逐只采集、TID及连续御三家现均接入兼容运行器共享预览；运行中监视窗口不再重复打开采集卡。同一后台任务各阶段复用预览端口，过渡期间自动重连；原始CLI高级测试仍不支持运行中共享预览。

动态穷举衔接和目标 SID 重试都还需要 Switch 实机验收，不能因单元测试或 `format` 通过就宣称稳定完成。

## TID 实测表

第三页“TID 实测表”记录工具新启动的 TID 单独流程和连续流程第一阶段的有效结果。游戏版本已移到 TID 基本条件中，关闭御三家连续流程也能选择；每次启动固定当时的火红/叶绿、Switch 1/2、语言和操作设置，不会跟随用户随后修改界面。

只记录实际 TID、OP/F1/F2 和相关操作参数，不记录 SID、SID ADV、F3。不同游戏、机型或参数永不合并；每次完整观测计一次，不累加脚本的去噪窗口次数。表页支持游戏/机型/完整 TID 筛选、详细设置和 CSV 导出，显示上限 1000 项但导出包含全部筛选结果。它是实测历史，不是穷举完成的理论 TID 表，不保证同参数再次命中。

r3会从运行日志取得实际OP机型补偿，并显示在详情及CSV中。非零补偿参与参数分组，防止新版NS2和旧版NS2混计；零补偿保持原参数键兼容，NS1旧记录仍可累计，不删除数据库。

`tid_records.py` 在日志运行器进程内解析原有日志并写入 `%LOCALAPPDATA%\FRLG-Auto-RNG\tid_records.sqlite3`，关闭主窗口后只要运行器继续，记录也继续。临时数据库占用只警告、保留待写记录并退避重试，不改变 ECS、按键顺序或校准算法。旧日志、更新前已启动的进程和高级页直接运行脚本不会自动补录；本次只更新源码版，未重新打包。

## 组成与职责

| 部分 | 职责 |
|---|---|
| Ten Lines Python 源码 | 按筛选条件生成目标状态，计算初始 Seed 与 Advance |
| `automation/planner.py` | 分层搜索、最高 IV 总和优先、同分最小 Advance、最大 Advance 限制 |
| `automation/easycon118.py` | 把普通或孵蛋结果写入对应 1.1.8 用户输入区，复制 `lib/ImgLabel`，预检 EasyCon/Tessdata |
| `automation/script_test.py` | 原地预检任意 ECS、核对直接标签引用、选择原始/兼容后端并准备内置冲浪结束探针 |
| EasyCon 1.6.4a `ezcon.exe` | 串口、采集卡、方法 1/5/14 标签和本地 Tesseract OCR、ECS 执行 |
| 1.1.8 | 命中、校准、投票、吃糖缩小 IV、抓捕和重试状态机 |

导入快照放在 `local_assets/easycon118/`，生成内容放在 `runtime/easycon118/`，计划记录放在 `rng_logs/plans/`；三者都是本机运行产物。安装器不原地修改下载目录原包，而是在导入快照中固化兼容修正，所以导入后的两份 1.1.8 主脚本可以直接运行，生成器再次处理时保持幂等。

高级模式的直接脚本页默认隐藏。启用后可选择任意 `.ecs`，使用“工具兼容运行器（正式工具）”或“原始 EasyCon 1.6.4-a CLI（A/B 对照）”运行。预检始终由固定原始 `ezcon.exe` 完成版本/哈希、两份火叶 OCR 模型和 `format` 检查，同时扫描所选主脚本及同目录 `lib/*.ecs` 的直接 `@标签` 引用；它不会执行搜索、参数替换、脚本复制或 1.1.8 完整语料指纹校验。运行日志统一写入 `runtime/script_tests/logs/`。所选脚本仍可任意控制手柄，因此该功能只用于已经人工审阅的测试工程，不是安全沙箱。

1.1.8 的静态白名单共 8 类、每版 30 只；首版界面开放 Starter、Fossil、Gift、GameCorner、Stationary、Legend、Event 共 27 只，游戏角会按版本区分飞天螳螂和凯罗斯。Roaming 三圣兽暂不开放：它们有火叶特有的截断 IV bug，还取决于本存档选择的御三家；普通六维 IV 分层会生成错误结果，必须另做搜索器后再接入。

## 标签兼容

当前 1150 个标签分布为：方法 1 共 17 个、方法 3 共 1 个、方法 5 共 777 个、方法 11 共 1 个、方法 14 共 354 个。仓库扩展 `闪公图标.IL` 专供 SID 反查读取闪光摘要页，`冲浪.IL` 专供孵蛋池塘流程确认冲浪操作已经结束；方法 14 必须保留原始 Alpha 通道作为 `TM_SQDIFF_NORMED` 的 mask。

Python 兼容层已统一到 `easycon/label_matcher.py`：

- 整帧先规范化到 1920×1080，非 16:9 输入拒绝匹配；
- 模板不按 `TargetWidth/TargetHeight` 缩放；
- 方法 14 保留包括半透明值在内的原 Alpha；
- ECS 整数匹配度使用向上取整，和 EasyCon 1.6.4a 一致；
- 标签惰性解码，并对重复 Base64 使用有限缓存。

当前审计标签指纹：`00d2fbfa9a3638f3cea64553e94b777ed8c5c63f813125617b50aaeed7c9d10e`。

SID 采集的能力范围不是按零努力值计算：HP、攻击、防御、特攻、特防、速度分别使用界面填写的对应努力值，并结合 Python 注入的完整第三世代种族值、手填初始等级、性格和 IV 0–31 生成合法范围。首次观测直接使用初始等级，成功喂糖后按观测序号递增，不再依赖闪光摘要底色上的等级 OCR。范围候选识别失败后即使完整数字标签得到数值，也必须再次验证该值位于合法范围内。闪光雄性摘要页使用仓库内置的 `assets/easycon118_extensions/闪公图标.IL`；普通底色的 `公图标` 不用于 SID 闪光雄性判定。1.1.8 原有种族值/性别表只覆盖其乱数目标，SID 页不得直接依赖这两张不完整表。

SID 采集每轮关闭游戏后，把旧的固定 `A → 1200 ms → A` 启动替换为按所选 Switch 机型执行 HOME_BUFFER。默认关闭稳定低分自适应时严格要求 95 分；开启后只允许同一状态连续 3 次得到相同、唯一最高且不低于 90 的分数时降低本次阈值。命中后仍按一次 `A` 返回游戏，并完整保留原来的 `WAIT 8000`、跳 OP 动画和进入存档操作。

## 孵蛋测试入口

新版 1.1.8 把孵蛋放在 `NS火叶全自动一键乱数1.1.8-TV时间轴测试.ecs`，当前只开放 Held 与 Pickup 使用同一初始 Seed 的流程。GUI 已把孵蛋拆成独立的“孵蛋（测试）”选项卡，需要填写游戏、主机、与 Ten Lines 一致的 Seed 模式、蛋种，以及 Ten Lines Egg 页给出的目标 Seed、Held/生成帧、Pickup/领取帧、双亲相性、双亲性别和 IV。蛋种输入框支持下拉选择、中文名、英文名和全国图鉴编号，并提供名称自动补全。Pickup 至少比 Held 晚 1800 帧。

配置按钮分为“亲本配置”和“全部配置”：亲本配置仅保存蛋种、相性、双亲性别与 IV；全部配置再保存游戏/主机、Seed 模式、Seed、Held/Pickup、254 步启动方式和 HOME_BUFFER 自适应。旧版配置可作为亲本配置载入；实验确认不持久化，载入后仍要求用户当次勾选。

当前时间轴模板还必须包含 `$孵蛋Held无蛋表Seed` 等 Held 无蛋区间字段。生成时报“模板字段实际为 0 次”通常表示忽略目录 `local_assets/easycon118` 没有从最新 1.1.8 包重新导入；刷新本地资产后再生成，不应放宽字段数量检查。

2026-08-26 更新后，目标 Seed 下的无蛋证据不再等 Pickup 达到稳定门槛才登记。Pickup 尚未稳定时只允许按连续确认的 Held 无蛋区间施加临时跳区，正式 Held 累计修正保持不变；连续无蛋超过配置上限会停止并保留诊断，避免死循环。

工具生成孵蛋运行副本时会固定写入 `$道具乱数模式 = 0`。时间轴模板本身可能保留作者最近一次道具测试的值，不能让该互斥开关泄漏到孵蛋运行参数中。

该流程默认自动执行 254 步准备和设置检查，也可选择从已经完成并保存的 254 步基础档开始。后一模式只跳过一次性走位、设置检查和存档，之后仍执行 HOME_BUFFER、野生 Seed 预校准、生成和领取两次命中、领取后野生 Seed 复核、骑车孵化，并按 Split → Normal → Alternate → Mixed 的顺序反查蛋个体和校正 Held/Pickup。公共设置的 HOME_BUFFER 稳定低分自适应默认关闭；开启后只允许同一状态连续 3 次得到完全相同、唯一最高且不低于 90 的分数时，把本次运行阈值从 95 降到该分数。该开关作用于 1.1.8 普通/孵蛋入口、TID 1.3.7 和 SID 查找生成副本，但不影响其他识图阶段。它已经通过 1.6.4a 编译与源码自测，但还没有完成本机实机验收。

导入器会把 1.6.4a 专用修正固化到本地 1.1.8 模板，GUI 生成孵蛋工程时再以幂等方式核对同一组代码：Options 页打开后等待 2 秒，文字速度、战斗动画、声音和按键模式各自最多识别 3 次；池塘到位后保留 500 ms，冲浪确认的第三次 `A` 前等待 2000 ms，之后最多约 50 秒等待 `冲浪 > 95`，确认冲浪操作结束后才按一次 `X` 并按原版时序继续，未命中时不按 `X`；随后还必须在名称 OCR 前确认已经进入野生战斗；Seed-only 校正复用正式版锁定与相邻 Seed 毫秒细调控制器，但不触碰 Held/Pickup 帧轴；领取后从能力页开始孵化前，以 5 次间隔 1500 ms 的 `B` 可靠退出各层菜单后才执行地图 `UP 200`。孵化收尾固定为 `WAIT 500 → B → WAIT 12000 → B → WAIT 1500 → B → WAIT 1500`。孵蛋运行日志自动保存为 `runtime/easycon118/egg-日期_时间.log`，会输出设置、冲浪与池塘战斗标签分数、Seed 控制器状态、孵化退页和骑车进度。

骑车孵化与定点波克比共用固定周期执行函数，不再检测 `蛋孵化` 标签。循环按第三世代额外周期公式、每轮 38 步和 1 轮安全余量计算；波克比的 10 周期对应 76 轮。完成后统一执行 `WAIT 500 → B → WAIT 12000 → B → WAIT 1500 → B → WAIT 1500` 收尾。定点波克比只替换原来的无限识图循环，领取对话、F2 和 TV/上车分支保持不变。

孵化后打开能力页复用普通反查的队伍页上移函数。普通新入队目标传 2；孵蛋正式轮的蛋位于第 5 位且第 6 位是复核野生，传 3。后续能力读取和吃糖重新识图继续走共享代码；每次升级得到的合法 IV 范围逐项取交集后再扫描候选，多个候选只有六项 IV 全部一致时才可停止喂糖，但 Egg 候选扫描仍使用专用孵蛋算法。

时间轴入口当前为 Held/Pickup 分别固定预校准 `230` 帧，请求值等于“目标帧 - 固定预校准 + 动态修正”；目标 `1115/3405` 的首轮请求因此为 `885/3175`。Held 反查窗为 `±100`，Pickup 为 `±2000`。固定预校准不被反查改写，动态修正独立累计；同一完整 IV 的多候选先按最近 Held 选择，若下一轮候选仍全部超出 `±20`，则用去除累计修正后的候选坐标匹配上轮轨迹。蛋能力页识别到闪光，或已确定候选中包含目标 Held/Pickup 时直接成功。

时间轴脚本的外层循环约定返回值 `2` 为重试、`0` 为终止。该修正已写入导入后的时间轴模板，而不再只存在于 GUI 生成副本：生成/领取/复核抓捕动作失败、领取后野生 Seed 反查失败和孵化动作失败均在重启后返回 `2`，因此单轮采集卡、识图或路线波动不会直接结束脚本。首次不领蛋的 Seed 预校准完成后，领取后 Seed 未命中会校正等待但继续保持“已预校准”；领取后野生反查失败也保持该状态，下一轮直接重新生成、领取和反查，不重复首次预校准。蛋反查已经确定同一套个体但 Held/Pickup 有误差时仍重启并自动校准；无候选、候选仍对应不同个体、吃糖达到上限、数据无效、HOME_BUFFER 失败或请求帧无效等终止分支直接返回 `0`，保留当前游戏画面，不再为了停止而重启游戏。包装器还要求日志出现“孵蛋流程测试完成/失败”；用户取消或异常提前退出会追加 `[EASYCON_DIAGNOSTIC]` 并由 GUI 明确报错。

## 仍需实机验证

代码级验证不能替代 Switch 实机长跑。开始正式刷取前仍要分阶段确认：

- 当前 1.6.4a 的串口连接、采集卡序号和 `Tessdata`；
- 短脚本能正常控制、停止和再次连接；
- 1.1.8 的存档位置、Seed 模式、道具和快捷键前置条件；
- 目标路线的重复命中、校准收敛、抓捕和长时间日志/进程行为；
- Python OpenCV 与 EasyCon 1.6.4a 原生识图在真实截图上的黄金分数容差。

预检会锁定 EasyCon `1.6.4-a+9c86137c…` 构建，并执行一次 `ezcon format` 语法解析；1.6.4a 没有 1.7.0 的 `ezcon ir` 命令。其他版本会先阻止启动，待重新核对接口和标签语义后再增加兼容配置。

因此，“搜索、选优、参数生成、ECS 语法预检和 CLI 接线”已经完成；“实机长跑稳定”尚未被本次代码检查证明。
