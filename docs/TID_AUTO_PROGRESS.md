# TID 自动读取进度

正式 PySide6 界面不再提供“刷新进度”按钮。默认开启“继续同参数的上次搜索进度”后，打开工具、切回 TID 页或停止脚本，进度区会自动更新；运行期间也会更新进度说明。

## 使用方式

- 继续上次任务：保留相同游戏、机型、语言及搜索参数，保持续跑开启，等待进度显示后生成方案并开始运行。
- 空闲时会把上次位置换算成 OP/F1/F2 总帧并显示在“穷举起点”。原搜索起点、范围、层级与任务身份仍然保留，不会因多次自动刷新反复叠加偏移。
- 已自动转入局部乱数时，起点显示对应的穷举返回位置；重新运行仍恢复局部搜索的壳层和已完成区域，不退回重搜。
- 想重新开始：取消续跑，或手动填写新起点。不会把历史进度强行覆盖到新参数上。
- 手动乱数的进度可以续跑，但不会填写穷举起点。已完成的任务不再恢复。

运行或后台生成任务期间只更新进度说明，不修改正在执行的输入，也不发送任何游戏按键。后台日志扫描不占用串口/采集卡；关闭窗口会取消扫描。

## 日志与检查点

运行器照常逐轮从原始输出保存 `tid_progress/*.json`。界面另在后台读取运行目录及用户目录 `logs/generated-plans` 中的 TID 日志：首次扫描，之后只读新增字节；目录发现缓存30秒，正在运行的日志直接加入读取，不等待目录缓存过期。

只有日志中的 `[TID进度] …/<配置摘要>.json` 与当前完整配置一致，且随后有完整、合法的 V3 `TIDPROGRESS` 机器行，才可恢复。配置摘要涵盖游戏、机型、语言、参数、连续流程、模板指纹和搜索版本。不同 SID ADV 尝试按各自上下文处理；非 TID 阶段的输出不能更新或完成 TID 进度。只有可见的几行 OP/F1/F2、旧版标记、缺少配置关联、截断或无效字段时不猜测恢复。

缺失的检查点可以从日志恢复；已有记录只有日志确实更新、累计轮数不倒退且没有同轮冲突时才推进。写入前取得与运行器相同的独占锁并再次读取检查点，活动运行器持锁时不写入。明确重新开始留下的空状态、已完成状态和损坏JSON均保留。原始日志只读，不改写或删除。

日志扫描结果应用前再次核对当前表单，切换参数或关闭续跑后丢弃迟到结果。起点的显示对应关系仍存于 `tid_settings.json` 的 `qt_progress_refill`，实际续跑仍交给原有工作进程，不改变 ECS、OP修正、SELECT、F1/F2/F3或去噪逻辑。
