# 设备标签诊断、修复与覆盖

相同游戏画面在不同采集卡、HDMI 转换链、色彩范围和缩放设置下，EasyCon 标签分数可能不同。工具按采集设备名称维护标签覆盖；正常脚本包保持原样。

## 从运行故障修复标签

修复提示默认开启，故障保护默认关闭，两项分别保存。主动开启保护后，已登记阶段的最终失败以退出码 20 停止脚本和输入，结束后等待完整事件最多 3 秒并自动提示一次。保护关闭时，仅明确的最终识别 / 采集错误提供诊断；未采集的分数、截图、语言或主机信息如实标出。普通低分、重试和旧故障不自动弹窗。

提示提供“开始修复”“查看完整日志”“稍后处理”。日志页的“打开故障标签修复”可打开已有事件。事件明确报告输入归零失败时，先手动确认控制器归零和画面稳定。

制作页的“本窗口引导”依次说明八步：

1. 确认现场：原图必须是预期且稳定的页面，勾选确认。错误页面先处理启动位置或采集设置。
2. 选择事件涉及的实际候选，核对当次加载备份、OR / AND 组和比较条件；候选低分不单独代表坏标签。
3. 编辑模板 / 搜索范围或导入 `.IL`。多文件逐项校验结构、重名冲突和验证结果，局部失败单独报告。
4. 执行同图原生测试，核对整数分数、阈值和搜索位置。
5. 执行三张新帧测试。没有共享通道时，用户主动点击“启动修复共享预览”；兼容运行器以 mock 控制端口持有选定的视频源，复用已有 MJPEG / FrameReader。读取启动之后的三个不同帧序号，不另开采集卡，不发送游戏按键。
6. 对 HOME / 退出 / 相邻动画等易混淆标签提供负样本检查。没有样本明确标为未验证。
7. 保存到当前设备前确认设备、标签、摘要、坐标、方法、条件和负样本范围；通过后事务保存并保留上一版。
8. 沿用原已选搜索结果重建并正常预检，显示待运行复测。由用户主动开始，再按同设备、同覆盖和原故障阶段确认效果。

保存标签前必须通过同图与三张新帧原生测试。相邻页面样本未提供时，界面会把这一项标为尚未验证。重建失败时，标签草稿、验证数据和故障事件仍会保留，事件状态不会显示为已应用。

阅读引导、保存草稿、覆盖已应用、运行已加载、实机已验证分别记录。退出码 0 不足以证明原故障阶段通过，事件保持待复测。“人工确认修复”仅在已应用 / 加载且实际覆盖 SHA-256 一致时可用，记录用户确认来源、设备、摘要、阶段和时间，不冒充自动采集的实机证据。

“恢复上一版”按指定标签的设备修改历史恢复内容，再按当前原目标重建。它不会修改其它标签、其它设备或原始脚本包。

## 手工导入与清理

在运行日志页的设备标签卡片中，可使用“制作 / 修复标签”、选择标签文件、选择文件夹、拖放 .IL 文件或清除当前设备覆盖。修复入口要求运行和设备任务已结束。普通手工导入沿用下方校验规则，并在之后生成的工程中生效。

清除覆盖只清理当前采集设备的档案。正在运行的工程不会热更新标签；保存、恢复或清理覆盖后，必须生成新的运行工程。

## 保存位置与事务记录

设备档案位于：

    %LOCALAPPDATA%/FRLG-Auto-RNG/device_label_overrides/<设备名称哈希>/

每个标签档案保存当前 .IL 和版本历史。设备清单登记原始标签包指纹、设备名称、每个覆盖文件 SHA-256 和修复来源。保存前检查 JSON、图片编码和尺寸、坐标、搜索方法，以及同名源标签的方法一致性。覆盖清单和标签文件使用临时文件、刷新到磁盘后原子替换；失败时尝试还原之前版本。

运行器故障事件位于：

    %LOCALAPPDATA%/FRLG-Auto-RNG/label_incidents/<事件编号>/

事件目录含标签阶段、运行参数、分数与比较条件、日志尾部、原分辨率 PNG、当次实际加载标签备份、验证结果和制作草稿。若当次标签备份缺失或数据校验失败，修复页不会假称已有原标签可直接编辑。

## 原生测试与判断

离线图像、故障截图和三张新采集帧都通过固定 EasyCon 1.6.4-a+9c86137 的 ImgLabel.Search()。工具按运行器提供给 ECS 的 Math.Ceiling 分数执行 >、>=、< 或 <= 判定。Python 预览不充当最终匹配依据。

动态测试保存每张新帧的原始 PNG、捕获序号、时间、标签 SHA-256、原生匹配分数和判定符。结果绑定当前设备、原图、分辨率、模板、范围、方法和阈值，任一项变化使旧验证失效。共享预览停止或切换时须重新测试，跨设备结果不能用于原事件。

## 运行前指纹检查

顺序固定为：

1. 检查原始 2.0 或 TID/SID 标签包；
2. 复制成独立运行工程；
3. 将设备档案中同名、同方法标签覆盖到工程；
4. 写入覆盖前后标签语料指纹和逐文件摘要；
5. 执行正式 EasyCon 1.6.4-a 格式 / 运行时预检。

原语料指纹仍会检查。高级模式“指纹仅警告”策略保留；缺失来源标签、非法 JSON、破损图像、坐标越界、未知结构、不同方法、跨设备验证等结构校验仍阻止运行。覆盖不绕过运行时预检。

本功能的代码和固定版本离线 / 新帧测试不等于 Switch 实机验收。正式验收还需在同一配置分别跑正常标签与故意不匹配标签，确认正常阶段推进、异常阶段停止输入并留存可用故障画面。
