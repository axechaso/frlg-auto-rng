# 设备标签诊断、修复与覆盖

相同游戏画面在不同采集卡、HDMI 转换链、色彩范围和缩放设置下，EasyCon 标签分数可能不同。工具按采集设备名称维护标签覆盖；正常脚本包保持原样。

## 从运行故障修复标签

1. 在 PySide6 工具中选择实际采集卡，并用工具兼容运行器启动方案。
2. 如果已登记的标签阶段超时、脚本重试达到上限或采集画面停止更新，运行器会取消脚本并锁住后续手柄输入；输入归零后保存故障事件。
3. 运行日志页的设备标签卡片显示故障阶段、失败类型、相关标签和故障截图。点击“重做此标签”打开制作页。
4. 确认原图确实属于预期游戏界面。核对搜索范围、目标矩形、搜索方法和比较条件；右键圈选范围或模板目标。
5. 先用“搜索测试”检查故障原图，再用“动态测试（3 张新帧）”。采集设备由当前兼容运行器持有，逐帧原图随验证记录保存。
6. 对容易与上一页或相邻动画页混淆的标签，再选择相邻状态截图执行“测试相邻页面截图”。
7. 通过同图和三张新帧测试后，选择“保存并用于当前设备”。如当前有已选方案，工具沿用已选搜索结果重建工程并执行原运行时预检；不会重新搜索另一个目标。

保存标签前必须通过同图与三张新帧原生测试。相邻页面样本未提供时，界面会把这一项标为尚未验证。重建失败时，标签草稿、验证数据和故障事件仍会保留，事件状态不会显示为已应用。

“恢复上一版”按指定标签的设备修改历史恢复内容，再按当前原目标重建。它不会修改其它标签、其它设备或原始脚本包。

## 手工导入与清理

在运行日志页的设备标签卡片中，可使用“制作 / 修复标签”、选择标签文件、选择文件夹、拖放 .IL 文件或清除当前设备覆盖。修复入口要求运行和设备任务已结束。普通手工导入沿用下方校验规则，并在之后生成的工程中生效。

清除覆盖只清理当前采集设备的档案。正在运行的工程不会热更新标签；保存、恢复或清理覆盖后，必须生成新的运行工程。

## 保存位置与事务记录

设备档案位于：

    %LOCALAPPDATA%/FRLG-Auto-RNG/device_label_overrides/<设备名称哈希>/

每个标签档案保存当前 .IL 和版本历史。设备清单登记原始标签包指纹、设备名称、每个覆盖文件 SHA-256 和修复来源。保存前检查 JSON、图片编码和尺寸、坐标、搜索方法，以及同名源标签的方法一致性。覆盖清单和标签文件使用临时文件、刷新到磁盘后原子替换；失败时尝试还原之前版本。

运行器故障事件位于：

    %LOCALAPPDATA%/FRLG-Auto-RNG/label_incidents/<事件编号>/

事件目录含标签阶段、运行参数、分数与比较条件、日志尾部、原分辨率 PNG、当次实际加载标签备份、验证结果和制作草稿。若当次标签备份缺失或数据校验失败，修复页不会假称已有原标签可直接编辑。

## 原生测试与判断

离线图像、故障截图和三张新采集帧都通过固定 EasyCon 1.6.4-a+9c86137 的 ImgLabel.Search()。工具按运行器提供给 ECS 的 Math.Ceiling 分数执行 >、>=、< 或 <= 判定。Python 预览不充当最终匹配依据。

动态测试保存每张新帧的原始 PNG、捕获序号、时间、标签 SHA-256、原生匹配分数和判定符。结果绑定当前采集设备；切换设备后不能保存为原设备事件的验证。

## 运行前指纹检查

顺序固定为：

1. 检查原始 2.0 或 TID/SID 标签包；
2. 复制成独立运行工程；
3. 将设备档案中同名、同方法标签覆盖到工程；
4. 写入覆盖前后标签语料指纹和逐文件摘要；
5. 执行正式 EasyCon 1.6.4-a 格式 / 运行时预检。

原语料指纹仍会检查。缺失来源标签、非法 JSON、破损图像、坐标越界、不同搜索方法、覆盖清单不符或生成工程被手动修改仍会阻止运行。覆盖不关闭高级模式的指纹校验。

本功能的代码和固定版本离线 / 新帧测试不等于 Switch 实机验收。正式验收还需在同一配置分别跑正常标签与故意不匹配标签，确认正常阶段推进、异常阶段停止输入并留存可用故障画面。
